## 1. 项目概述

### 1.1 目标
在 GameJam 时限内交付 **2D 俯视网格解谜游戏（Growth，暂定代号 "绳蛇解谜"）** 的可玩原型并打磨导出。核心机制：主角身长受限、机关随步数生长挤压空间、规划路线进入终点。强调循环清晰、可推演、扩展友好。

### 1.2 技术栈
| 项 | 选择 | 说明 |
|----|------|------|
| 引擎 | Godot 4.7 stable（标准版） | GDScript，不依赖 mono |
| 语言 | GDScript | 单语言，不混 C# |
| 渲染 | Forward+ | Windows RenderingDevice = d3d12 |
| 2D 拉伸 | `canvas_items` / `expand` | 保证任意窗口比例无黑边 |
| 窗口 | 1280×720 | viewport 尺寸 |
| 入口场景 | `Scenes/UI/MainMenu.tscn` | 开始界面 → 选关 → 关卡场景 |
| 输入 | 内置 `[input]` 动作 | WASD 移动 + `restart`(R) + `pause` |
| 存档 | `user://`（SaveManager） | 每关最佳步数（测试期全开，不锁关） |
| VCS | Git + Git LFS | 远端 `github.com/YICIYUAN-GAME-DEPARTMENT/Growth` |

### 1.3 里程碑
- **M0 工程与规范**：架构、本文档、功能需求文档、环境、AGENTS/技能 —— ✅（本次）
- **M1 可玩竖切**：主菜单→选关→Level_Example：移动（身长硬上限）/截断/食物/机关生长/BFS死局→胜负 —— ✅（本次原型）
- **M2 内容铺量**：正式 8 关（复制 LevelTemplate 直编）+ 数值 Balance 调优 + 音效/占位美术打磨
- **M3 打磨导出**：平衡、教程文案、导出（含 LFS 完整性检查）

## 2. 架构设计

> 详细分层、Autoload 接口、事件总线说明见 [docs/architecture/架构说明.md](architecture/架构说明.md)（本文 §2 为其概要权威）。

### 2.1 分层
```
Autoload 单例（全局，跨场景存活）        GameManager(balance) / EventManager / ResourceManager / AudioManager / SaveManager
  ↓
Systems（由关卡脚本/持有）               Level.gd（编排）/ GridSystem（纯数据+BFS）
  ↓
Entities（实体节点，设计者摆进关卡场景）   PlayerSpawn / Obstacle / Food / Goal / Mechanism(5阶段)
  ↓
Scenes（窗口级场景，change_scene 切换）  UI(MainMenu·LevelSelect) / Scenes/Levels/Level_<nn>.tscn
  ↓
数据                                 Balance.tres（全局数值，唯一 .tres）；关卡布局=场景本身
```

**依赖方向：** Autoload ← 关卡 ← 实体 ← Scenes；数据仅 Balance。禁止反向依赖。

### 2.2 通信原则
- 跨系统通信用信号，统一走 `EventManager.*`；禁止 `get_node("/root/OtherSystem")` 硬引用。
- 关卡场景直接 `load()` 自己的 .tres 类脚本/数值资源；避免 `ResourceManager` 缓存造成编辑器热更问题（可选）。
- 音频走 `AudioManager.play_sfx/play_music`；禁止业务代码自建 `AudioStreamPlayer`。
- 场景流转走 `GameManager.change_scene()` / 由 `GameManager.start_level` 进入关卡；禁止裸 `change_scene`。
- **全局数值唯一来源：** `Balance.tres`（§5.5）+ [功能需求文档](design/功能需求文档.md) §7。脚本内禁止硬编码玩法数值。

### 2.3 扩展点（玩法新增/修改的接法）
- 新增实体 → `Scenes/Entities/<Xxx>.tscn` 预制 + `Scripts/Entities/<Xxx>.gd`，直接摆进关卡场景。
- 新增关卡 → 复制 `Scenes/Levels/LevelTemplate.tscn` 为 `Level_<nn>_<名>.tscn`，摆实体，改导出 level_id/name。
- 修改全局数值 → 只改 `Resources/Config/Balance.tres`；规则性变更需改 [功能需求文档](design/功能需求文档.md) 并走 PR。
- 新增全局信号 → 追加到 `EventManager` 末尾 `## Gameplay` 区块；**勿删改既有信号签名**。

## 3. 资源与命名规范

### 3.1 总则
- 资源放 `res://` 对应目录，禁止散落根目录。
- 文本类（`.gd/.tscn/.tres/.cfg/.import`）永不入 LFS；大二进制（图/音频/模型）走 LFS（§3.8）。
- 新增美术/音频资源必须登记进 §3.9 资产清单，避免重复制作。

### 3.2 图片/贴图导入
| 用途 | 建议设置 |
|------|---------|
| TileSet 网格底图 / 障碍 / 机关占格 | 关闭 Mipmap、`filter=false`（像素感）或 `true`（高清），按最终美术决定 |
| 角色/机关/食物/终点精灵 | Lossy，Mipmap Off，HDR Off |
| UI | Lossless，Mipmap Off |

未定规格先默认导入，并在 §3.9 标注【待定】。

### 3.3 命名规范
统一格式：`<前缀>_<名称>_<序号>`，全大写下划线；资源文件禁止中文与空格。

| 前缀 | 含义 | 示例 |
|------|------|------|
| `CHR` | 主角/机关/食物/终点等实体贴图 | `CHR_Player_Head_01`、`CHR_Mech_Stage_03` |
| `TILE` | TileSet 底图/障碍图块 | `TILE_Floor_01`、`TILE_Wall_01` |
| `UI` | HUD 图标/按钮 | `UI_Btn_Restart_01` |
| `SFX` | 音效 | `SFX_Food_Eat_01`、`SFX_Mech_Grow_01` |
| `MUS` | 音乐 | `MUS_Puzzle_Amb_01` |

- 场景/脚本文件用 `PascalCase`（`Level_01_Intro.tscn` 的关卡名段可用 snake；见 §4.2 命名规则）。
- 版本号两位递增，重大改动 +1。

### 3.4 目录职责
| 目录 | 放什么 | 不放什么 |
|------|--------|---------|
| `Scenes/` `Scenes/Levels/` `Scenes/UI/` `Scenes/Entities/` | 场景/预制（关卡即场景，见 §4） | 二进制美术 |
| `Scripts/` `Scripts/Autoload/` `Scripts/Systems/` `Scripts/Entities/` `Scripts/UI/` `Scripts/Data/` `Scripts/Utils/` | GDScript | 二进制 |
| `Resources/Config/` | `Balance.tres`（唯一数值数据） | — |
| `Art/Sprites/` `Art/Tiles/` `Art/UI/` | 美术 | 脚本/数据 |
| `Audio/SFX/` `Audio/Music/` | 音频 | — |
| `UI/Theme/` `UI/Fonts/` | 主题/字体 | — |
| `docs/` | 权威文档/技能/规则 | — |

### 3.5 音频导入
- BGM 用 Ogg（可循环），SFX 用 Wav；少用 mp3。
- SFX `loop=false`；BGM `loop=true`。
- 总线：`Master → Music / SFX`，UI 音走 SFX。

### 3.6 字体
- `.ttf/.otf` 入 LFS；系统默认字体可在原型期直接使用。

### 3.7 占位资源
- 未定稿美术用纯色矩形/线框占位：命名加 `_TMP` 后缀，正式替换后删除占位并在 §3.9 更新。
- 占位资源同样登记 §3.9，状态标【待定】。

### 3.8 Git LFS 规则
- `.gitattributes` 已按扩展名追踪：`png/jpg/jpeg/webp/bmp/tga/psd/kra/aseprite/glb/gltf/fbx/obj/wav/ogg/mp3/flac/ttf/otf/ogv/mp4/zip`。
- 大资源（>~500KB 或上述类型）自动入 LFS；提交信息用 `asset` 前缀并注明 A-xx 资产编号。
- 禁止 LFS 追踪 `.gd/.tscn/.tres/.cfg/.import`。
- 入库流程见 [collaboration-rules §4](agents/rules/collaboration-rules.md)。

### 3.9 资产清单（A-xx 编号）
> 新增资源在此登记；AI 智能体制作前先查此表。**仅登记美术/音频/关卡数据等"资产"**；代码场景/脚本不登记。

| 编号 | 名称 | 路径 | 类型 | 状态 | 备注 |
|------|------|------|------|------|------|
| A-01 | 项目图标 | `res://icon.svg` | 2D | ✅ | 复用 Godot 默认亦可 |
| A-02 | 主角头部占位 | `res://Art/Sprites/CHR_Player_Head_01_TMP.png` | 2D | 【待定】 | 或纯色节点，无需资产 |
| A-03 | 机关占位 | `res://Art/Sprites/CHR_Mech_Stage_01_TMP.png` | 2D | 【待定】 | 可先画 5 阶段 |
| A-04 | 食物/终点占位 | `res://Art/Sprites/` | 2D | 【待定】 | — |

## 4. 场景与节点组织

### 4.1 通用约定
- 关卡场景根节点挂 `Scripts/Systems/Level.gd`（Node2D）；UI 根为 `Control`。
- **UI / 贴图 / 布局一律用编辑器场景树组织**；脚本不 `_draw` 画面、不 `new` 控件。动态内容（玩家身体格/机关占格/食物消失）由脚本同步到场景中已存在的 TileMap 层与节点。
- 节点名 PascalCase，变量名 snake_case；`@onready` 缓存节点，禁止在 `_process` 反复 `get_node`。
- 信号连接集中在 `_ready()` 顶部声明。
- 网格玩法不依赖物理碰撞：背景/障碍用 `TileMapLayer` 涂格，判定走 `GridSystem` 数据。

### 4.2 场景文件（目录职责呼应 §3.4）
| 场景 | 职责 |
|------|------|
| `Scenes/UI/MainMenu.tscn` | 主菜单（开始/退出），**游戏入口**，控件全在场景树 |
| `Scenes/UI/LevelSelect.tscn` | 选关：扫描 `Scenes/Levels/Level_*.tscn`（测试期全开） |
| `Scenes/UI/LevelHUD.tscn` | 局内顶栏 + 结算覆盖（作为关卡子场景实例） |
| `Scenes/Levels/Level_<nn>_<名>.tscn` | **每个关卡一个场景**（根挂 Level.gd），Ground/Obstacles 用 TileMap 涂格 + 实体节点 |
| `Scenes/Levels/LevelTemplate.tscn` | 新建关卡模板（复制改名即可） |
| `Scenes/Entities/*.tscn` | PlayerSpawn / Food / Goal / Mechanism（仅贴图节点） |

> 设计者操作手册见 [docs/development/关卡制作指南.md](development/关卡制作指南.md)。

### 4.3 场景流转
```
MainMenu.tscn ──▶ LevelSelect.tscn ──▶ Scenes/Levels/Level_<nn>.tscn
        ▲                ▲                     │ 胜利/失败
        └── 返回主菜单 ◀──┴── 返回选关 ◀────────┘
```
无持久根场景；每个窗口是完整场景，切场景用 `GameManager.change_scene()`。

### 4.4 关卡场景结构（场景直编）
```
Level_01_xxx (Node2D, Level.gd)              ← 只做规则逻辑
├── Ground        (TileMapLayer)             ← 手涂地板；留空格运行时兜底铺默认地板
├── Obstacles     (TileMapLayer)             ← 涂障碍：被涂的格=不可走
├── EntityRoot    (Node2D)                   ← 设计者在这里摆实体
│   ├── PlayerSpawn (PlayerSpawn.tscn)       ← 1 个出生点 S
│   ├── Goal        (Goal.tscn)              ← 终点 E
│   ├── Food..      (Food.tscn)              ← 食物（单贴图）
│   └── Mechanism.. (Mechanism.tscn)         ← 机关核心（Core 单贴图）
├── MechanismCells (TileMapLayer)            ← 机关生长体（运行时同步实际占格）
├── PlayerCells    (TileMapLayer)            ← 玩家头/身（运行时按 trail 同步）
├── LevelHUD       (instance: Scenes/UI/LevelHUD.tscn)
└── Camera2D（运行时创建）
```
- 图层/节点绘制贴图：`Art/Tiles/GameTiles.tres`（TileSet：地板/障碍/机关体/玩家头/玩家身五枚 tile）+ `Art/Sprites/*.svg`（实体单贴图）。
- 实体位置语义：实体节点导出 `cell: Vector2i`，节点 position=格中心；编辑器拖动自动吸附格子。
- 地板/障碍 TileMap 的画法：直接选 `Ground`/`Obstacles` 层用 TileMap 画笔涂；关卡逻辑读取这两层生成障碍/地图范围。
- 机关：核心=自身 Core 贴图；生长体占格=代码 `MechanicShapes` + 占格冲突，运行时整层重涂到 `MechanismCells`（**边界改变自动套用**，被玩家挡住跳过的格不会误显示）。

### 4.5 暂停与输入锁
- 暂停：`GameManager.pause_game()`/`resume_game()`。
- **机关生长动画期间输入锁**（≤0.3s）：`input_locked=true`，`Level._unhandled_input` 忽略移动输入；`restart`(R) 始终可用。

## 5. 数据定义与数值配置

### 5.1 通用规则
- **关卡布局不做成数据文件**：关卡 = 场景直编（§4.4）。
- 唯一 `.tres` 数据 = 全局数值 `Resources/Config/Balance.tres`（类 `Balance`，`@export`，可 Inspector 直接调）。
- 自定义资源类脚本放 `Scripts/Data/`（`Balance.gd`、`MechanicShapes.gd`、`GridMetrics.gd`），`class_name` PascalCase 与文件同名。

### 5.2 关卡场景导出字段（权威，Level.gd）
| 导出 | 类型 | 说明 |
|------|------|------|
| `level_id` | int | 唯一编号（LevelSelect 排序/记录步数用） |
| `level_name` | String | 选关显示名 |
| `map_size` | Vector2i | 保底网格（默认 32×32）；运行时自动扩到覆盖所有实体占格 |

实体子节点（PlayerSpawn/Obstacle/Food/Goal/Mechanism）均导出 `cell: Vector2i`；Mechanism 另导出 `initial_level`。

### 5.3 机关生长（实现层事实，源自玩法规则）
- 阶段 `lv ∈ [0,4]`，形状含中心、逐级嵌套（**权威表见 [功能需求文档](design/功能需求文档.md) §4.2.1**）。
- 逻辑占格 `Mechanism.claimed`（只增不减）：每次生长 `claim_missing(blocked)`，blocked=玩家身体+起点+终点（保护格）。
- **占格即时生效**：生长当帧更新 `GridSystem.mech_cells`，动画 ≤0.3s 锁输入，动画后跑死局检查。
- 机关渲染：核心=Core 贴图；生长体占格同步到关卡 `MechanismCells` TileMapLayer（无 Stage 预览场景）。

### 5.4 进度存档（SaveManager）
- Autoload `SaveManager`（`Scripts/Autoload/SaveManager.gd`），文件 `user://growth_save.cfg`（ConfigFile）。
- 内容：`best_steps`（Dictionary `level_<id>` → 步数）。
- 接口：`record_result(level_key, steps)` / `best_steps_for(key)` / `has_cleared(key)`。
- 胜利时记录；测试期不做关卡锁定。

### 5.5 数值配置（Balance.tres）
- 文件 `Resources/Config/Balance.tres`（类 `Scripts/Data/Balance.gd`），集中放全局数值（`@export`）：
  `initial_max_len=3`、`food_len_gain=2`、`mech_level_max=4`、`growth_step_interval=6`、`grow_anim_sec=0.3`。
- 运行入口：`GameManager.balance` 只读；脚本不得硬编码数值；**数值权威清单见 [功能需求文档](design/功能需求文档.md) §7**。

### 5.6 测试基准数值（QA 回归速查，权威出处=功能需求 §7）
| 项 | 基准 | 说明 |
|----|------|------|
| 网格 | 默认 32×32 | 运行时自动扩到实体覆盖范围 |
| 初始最大身长 L | 3 | HUD 显示 L；trail 长度硬上限 ≤ L，S→head 连续 |
| 食物加长 | +2/个 | 仅增 L，不触发机关 |
| 机关形状 | 中心恒占；lv0–4 总占 1/5/9/13/21 | 去中心 0/4/8/12/20（权威表见功能需求 §4.2.1） |
| 生长节奏 | 每 6 有效步 → 全体机关+1 阶段 | 截断也算；占格即时生效；动画 ≤0.3s 锁输入 |
| 步数计数 | 仅有效移动/截断 +1 | 无效移动不计步；身长达 L 前进空格被禁（不计步） |
| 胜负 | 踏入终点=胜；BFS 无通路=败 | BFS 忽略身长与身体（保护格=起点/终点不占） |
| 关卡/解锁 | 场景直编 `Level_*.tscn`；测试期全开 | LevelSelect 自动扫描 |

## 7. 提交与协作

见 [docs/agents/rules/collaboration-rules.md](agents/rules/collaboration-rules.md) 与 [docs/agents/rules/coding-rules.md](agents/rules/coding-rules.md)。要点：
