## 1. 项目概述

### 1.1 目标
在 GameJam 时限内交付 **2D 俯视网格解谜游戏（Growth，暂定代号 "绳蛇解谜"）** 的可玩原型并打磨导出。核心机制：主角身长受限、机关随步数生长挤压空间、规划路线进入终点。强调循环清晰、可推演、扩展友好。

### 1.2 技术栈
| 项 | 选择 | 说明 |
|----|------|------|
| 引擎 | Godot 4.7 stable（标准版） | GDScript，不依赖 mono |
| 语言 | GDScript | 单语言，不混 C# |
| 渲染 | Forward+ | Windows RenderingDevice = d3d12 |
| 2D 拉伸 | `canvas_items` / `expand` | 保证任意窗口比例无黑边 |
| 窗口 | 1280×720 | viewport 尺寸 |
| 入口场景 | `Scenes/UI/MainMenu.tscn` | 开始界面 → 选关 → 关卡场景 |
| 输入 | 内置 `[input]` 动作 | WASD 移动 + `restart`(R) |
| 存档 | `user://`（SaveManager） | 每关最佳步数（测试期全开，不锁关） |
| VCS | Git + Git LFS | 远端 `github.com/YICIYUAN-GAME-DEPARTMENT/Growth` |

### 1.3 里程碑
- **M0 工程与规范**：架构、本文档、功能需求文档、环境、AGENTS/技能 —— ✅（本次）
- **M1 可玩竖切**：主菜单→选关→Level_01：移动（身长硬上限）/截断/食物/机关生长/BFS死局→胜负 —— ✅
- **M2 内容铺量**：按关卡清单（见功能需求 §6.1）铺关卡（复制 LevelTemplate 直编）+ 数值调优 + 占位美术打磨
- **M3 打磨导出**：平衡、教程文案、导出（含 LFS 完整性检查）

## 2. 架构设计

> 详细分层、Autoload 接口、事件总线说明见 [docs/architecture/架构说明.md](architecture/架构说明.md)（本文 §2 为其概要权威）。

### 2.1 分层
```
Autoload 单例（全局，跨场景存活）        GameManager(balance/场景流转) / EventManager / SaveManager
  ↓
Systems（由关卡脚本/持有）               Level.gd（编排）/ GridSystem（纯数据+BFS）
  ↓
Entities（实体节点，设计者摆进关卡场景）   PlayerSpawn / Food / Goal / Mechanism（障碍=Obstacles 层涂格，非实体）
  ↓
Scenes（窗口级场景，change_scene 切换）  UI(MainMenu·LevelSelect) / Scenes/Levels/Level_<nn>.tscn
  ↓
数据                                 Balance.tres（全局数值，唯一 .tres）；关卡布局=场景本身
```

**依赖方向：** Autoload ← 关卡 ← 实体 ← Scenes；数据仅 Balance。禁止反向依赖。

### 2.2 通信原则
- 跨系统通信用信号，统一走 `EventManager.*`；禁止 `get_node("/root/OtherSystem")` 硬引用。
- 资源/场景获取一律显式 `load()`（原型规模不引入缓存 Autoload）；禁止在移动/生长等热路径反复 `load()`。
- 场景流转走 `GameManager.change_scene()` / 由 `GameManager.start_level` 进入关卡；禁止裸 `change_scene`。
- **全局数值唯一来源：** `Balance.tres`（§5.5）+ [功能需求文档](design/功能需求文档.md) §7。脚本内禁止硬编码玩法数值。

### 2.3 扩展点（玩法新增/修改的接法）
- 新增实体 → `Scenes/Entities/<Xxx>.tscn` 预制 + `Scripts/Entities/<Xxx>.gd`（extends `CellEntity`），直接摆进关卡场景。
- 新增关卡 → 复制 `Scenes/Levels/LevelTemplate.tscn` 为 `Level_<nn>_<名>.tscn`，摆实体，改导出 level_id/name。
- 修改全局数值 → 只改 `Resources/Config/Balance.tres`；规则性变更需改 [功能需求文档](design/功能需求文档.md) 并走 PR。
- 新增全局信号 → 追加到 `EventManager` 的 `## Gameplay` 区块；**勿删改既有 emit 中的信号签名**（新增后同步架构说明 §3）。

## 3. 资源与命名规范

### 3.1 总则
- 资源放 `res://` 对应目录，禁止散落根目录。
- 文本类（`.gd/.tscn/.tres/.cfg/.import`）永不入 LFS；大二进制（图/音频/模型）走 LFS（§3.8）。
- 新增美术/音频资源必须登记进 §3.9 资产清单，避免重复制作。

### 3.2 图片/贴图导入
| 用途 | 建议设置 |
|------|---------|
| TileSet 网格底图 / 障碍 / 机关占格 | 关闭 Mipmap、`filter=false`（像素感）或 `true`（高清），按最终美术决定 |
| 角色/机关/食物/终点精灵 | Lossy，Mipmap Off，HDR Off |
| UI | Lossless，Mipmap Off |

未定规格先默认导入，并在 §3.9 标注【待定】。

### 3.3 命名规范
统一格式：`<前缀>_<名称>_<序号>`，全大写下划线；资源文件禁止中文与空格。

| 前缀 | 含义 | 示例 |
|------|------|------|
| `CHR` | 主角/机关/食物/终点等实体贴图 | `CHR_Player_Head_01`、`CHR_Mech_Core_01` |
| `TILE` | TileSet 底图/障碍图块 | `TILE_Floor_01`、`TILE_Wall_01` |
| `UI` | HUD 图标/按钮 | `UI_Btn_Restart_01` |
| `SFX` | 音效 | `SFX_Food_Eat_01`、`SFX_Mech_Grow_01` |
| `MUS` | 音乐 | `MUS_Puzzle_Amb_01` |

- 场景/脚本文件用 `PascalCase`（`Level_01_Intro.tscn` 的关卡名段可用 snake；见 §4.2 命名规则）。
- 工具生成的原型贴图为小写 snake 路径（`player_head.svg`/`terrain_floor.svg` 等，代码直接引用），正式美术替换时按上表大写命名并更新引用。
- 版本号两位递增，重大改动 +1。

### 3.4 目录职责
| 目录 | 放什么 | 不放什么 |
|------|--------|---------|
| `Scenes/` `Scenes/Levels/` `Scenes/UI/` `Scenes/Entities/` | 场景/预制（关卡即场景，见 §4） | 二进制美术 |
| `Scripts/Autoload/` `Scripts/Systems/` `Scripts/Entities/` `Scripts/UI/` `Scripts/Data/` | GDScript | 二进制 |
| `tools/` | 生成/迁移/一次性工具（Godot 脚本+场景，运行不参与） | 游戏内引用 |
| `Resources/Config/` | `Balance.tres`（唯一数值数据） | — |
| `Art/Sprites/` `Art/Tiles/` `Art/UI/` | 美术 | 脚本/数据 |
| `Audio/SFX/` `Audio/Music/` | 音频（本版无素材，占位） | — |

### 3.5 音频导入
> 本版**不接入音频**（无素材、无 AudioManager）；下列规范供后续接入时使用，素材入库后登记 §3.9。
- BGM 用 Ogg（可循环），SFX 用 Wav；少用 mp3。
- SFX `loop=false`；BGM `loop=true`。
- 总线：`Master → Music / SFX`，UI 音走 SFX。

### 3.6 字体
- `.ttf/.otf` 入 LFS；系统默认字体可在原型期直接使用。

### 3.7 占位资源
- 未定稿美术用纯色矩形/线框占位：命名加 `_TMP` 后缀，正式替换后删除占位并在 §3.9 更新。
- 占位资源同样登记 §3.9，状态标【待定】。

### 3.8 Git LFS 规则
- `.gitattributes` 已按扩展名追踪：`png/jpg/jpeg/webp/bmp/tga/psd/kra/aseprite/glb/gltf/fbx/obj/wav/ogg/mp3/flac/ttf/otf/ogv/mp4/zip`。
- 大资源（>~500KB 或上述类型）自动入 LFS；提交信息用 `asset` 前缀并注明 A-xx 资产编号。
- 禁止 LFS 追踪 `.gd/.tscn/.tres/.cfg/.import`。
- 入库流程见 [collaboration-rules §4](agents/rules/collaboration-rules.md)。

## 4. 场景与节点组织

### 4.1 通用约定
- 关卡场景根节点挂 `Scripts/Systems/Level.gd`（Node2D）；UI 根为 `Control`。
- **UI / 贴图 / 布局一律用编辑器场景树组织**；脚本不 `_draw` 画面、不 `new` 控件。动态内容（玩家身体格/机关占格/食物消失）由脚本同步到场景中已存在的 TileMap 层与节点。
- 节点名 PascalCase，变量名 snake_case；`@onready` 缓存节点，禁止在 `_process` 反复 `get_node`。
- 信号连接集中在 `_ready()` 顶部声明。
- 网格玩法不依赖物理碰撞：背景/障碍用 `TileMapLayer` 涂格，判定走 `GridSystem` 数据。

### 4.2 场景文件（目录职责呼应 §3.4）
| 场景 | 职责 |
|------|------|
| `Scenes/UI/MainMenu.tscn` | 主菜单（开始/设置/退出），**游戏入口**，控件全在场景树 |
| `Scenes/UI/LevelSelect.tscn` | 选关：扫描 `Scenes/Levels/Level_*.tscn`（测试期全开，**自动排除 LevelTemplate**）；圆角正方形选项仅显示 `level_id` 数字 |
| `Scenes/UI/LevelHUD.tscn` | 局内顶栏 + 结算覆盖（作为关卡子场景实例） |
| `Scenes/Levels/Level_<nn>_<名>.tscn` | **每个关卡一个场景**（根挂 Level.gd），Ground/Obstacles 用 TileMap 涂格 + 实体节点 |
| `Scenes/Levels/LevelTemplate.tscn` | 新建关卡模板（复制改名即可） |
| `Scenes/Entities/*.tscn` | PlayerSpawn / Food / Goal / Mechanism（贴图子节点） |

> 设计者操作手册见 [docs/development/关卡制作指南.md](development/关卡制作指南.md)。

### 4.3 场景流转
```
MainMenu.tscn ──▶ LevelSelect.tscn ──▶ Scenes/Levels/Level_<nn>.tscn
        ▲                ▲                     │ 胜利/失败
        └── 返回主菜单 ◀──┴── 返回选关 ◀────────┘
```
无持久根场景；每个窗口是完整场景，切场景用 `GameManager.change_scene()`。

### 4.4 关卡场景结构（场景直编）
```
Level_01_xxx (Node2D, Level.gd)              ← 只做规则逻辑
├── World        (Node2D, 默认 0,0)          ← 内容容器；运行时不自动移动
│   ├── Ground        (TileMapLayer)         ← 手涂地板；地图范围内空格兜底补地板
│   ├── Obstacles     (TileMapLayer)         ← 涂障碍：被涂的格=不可走
│   ├── EntityRoot    (Node2D)               ← 设计者在这里摆实体
│   │   ├── PlayerSpawn (PlayerSpawn.tscn)   ← 1 个出生点 S
│   │   ├── Goal        (Goal.tscn)          ← 终点 E
│   │   ├── Food..      (Food.tscn)          ← 食物（单贴图）
│   │   └── Mechanism.. (Mechanism.tscn)     ← 机关核心（Core 单贴图）
│   ├── MechanismCells (TileMapLayer)        ← 机关生长体（运行时同步实际占格，含核心格）
│   ├── PlayerCells    (TileMapLayer)        ← 玩家管道中段连接件 + 头/尾端点半截瓦（运行时按 trail 同步）
│   └── PlayerFx       (Node2D)              ← 头/尾独立 Sprite：Head（跟 head 格，z_index=1 可叠尾上）、
│                                              Tail（固定在 S，开局即显示）；容器隐藏由 Level 运行时强制 visible
├── LevelHUD       (instance: Scenes/UI/LevelHUD.tscn)
└── Cam            (Camera2D)                ← 作者自摆；运行时不移动、不缩放
```
- 图层贴图：`Ground`→`TerrainFloor.tres`、`Obstacles`→`TerrainWall.tres`、`MechanismCells`→`TerrainMech.tres`——**三张独立纹理**（`terrain_floor/wall/mech.svg`），瓦片坐标 = `(mask, 行)`：floor/wall 仅 row0（16 变体 4 角自动贴边），mech 3 帧行（出场动画用）；`PlayerCells`→`PlayerSnek.tres`（管道连接件+端点瓦）；实体单贴图 `Art/Sprites/*.svg`。
- **玩家视觉（管道身体 + 头/尾贴图）**：
  - 身体=PlayerCells 瓦片：**中段只画前后都有格子的中间格**，`player_snek.svg`（320×32）row0 col0..5=连接件（0=横直 1=竖直 2=弯NE 3=弯NW 4=弯SW 5=弯SE），每格从中心伸到相邻格边（宽 14）、一格连前/后两格，相邻拼成连续"管道"；**头格/尾格各垫 col6..9 端点半截瓦**（6=E 7=W 8=S 9=N，中心→边），把管道平滑接进头/尾底下——端点瓦先于 PlayerFx 绘制，被贴图盖住的部分即形成"从贴图底下接入"的过渡，由 `_sync_player_layer` 按 trail 端点方向选片。
  - 头/尾=独立 Sprite 贴图（非瓦片、**可大于单格**）：`World/PlayerFx/Head`（`Art/Sprites/player_head.svg`，**精灵表 hframes=3 × vframes=4**：4 行方向 0=E 1=W 2=S 3=N **各画各的纹理、不旋转**；帧列 0/1=移动两帧循环、2=停留帧——每有效步 `_advance_head_walk` 交替推进帧列，停下 `HEAD_IDLE_SEC=0.35s` 后固定停留帧）位于 head 格；`World/PlayerFx/Tail`（`Art/Sprites/player_tail.svg`）固定在出生点 S、朝向身体延伸方向旋转，**从开局（n=1）即显示**；起步/回到起点（n=1，头与尾同格）时 Head 以 `z_index=1` 叠放在 Tail 之上。`_update_end_sprites` 每次行动后按轨迹定位。
  - **头/尾按"接口点"锚定**：Sprite2D 按帧中心定位（hframes/vframes 每格画布中心=接口点=格中心），画布可大于单格（居中溢出）。内容不在帧中心的正式美术，用 Sprite2D.offset 把接口点移到格中心。
  - 由 `tools/GenSnek.gd` 生成（先跑 svg → `--import` → 带 `-- --tres-only` 再跑一次；管道图集 320×32、头精灵表 132×176、尾 48×48 由生成器分别输出）。
- 实体位置语义：实体节点导出 `cell: Vector2i`，节点 position=格中心；编辑器拖动自动吸附格子（吸附逻辑集中在 `CellEntity` 基类）。
- 地板/障碍 TileMap 画法：在 `Ground`/`Obstacles` 层上选 Terrain 画笔涂格，引擎按 **4 角连接位**自动挑 16 变体拼边；关卡逻辑读取这两层生成障碍/地图范围，未涂的空格在包围盒内兜底补地板。**运行时贴边=确定性直写**：`_paint_auto` 按格集几何算掩码写瓦片，只写给定格、绝不外扩。
- **贴图替换契约（画完地图免重画的关键）**：三类地形各用一张独立纹理——`terrain_floor.svg` / `terrain_wall.svg`（各 512×32）与 `terrain_mech.svg`（512×96，row0/1/2=生长动画帧 0=冒出 1=生长中 2=完成）；每行 16 列，列索引 = 4 角掩码（bit0=左上 bit1=右上 bit2=左下 bit3=右下）。正式美术替换各纹理时必须保持「行列位置 + 角序」不变——TileMap 格子存的是列号（连接规则），换图即自动换皮；机关纹理需保证 row2（完成帧）与既有格外观一致。布局与 .tres 由 `tools/GenPlaceholderAtlas.gd` / `tools/GenTerrainTileset.gd` 生成（**注意：工具重存 .tres 会丢 uid 头，重生成后须把 `uid="uid://…"` 补回首行**）；需重铺已有场景时用 `tools/MigrateTerrain.tscn` / `tools/RebuildLevelTiles.tscn` 确定性直写（勿用编辑器外扩式 terrain connect 批量重画）。
- **位置即所见：** World/Cam 是普通场景节点，脚本运行时不自动移动/缩放——编辑器摆哪，游戏就显示哪。
- 机关：生长体占格=代码 `MechanicShapes` + 占格冲突，运行时整层确定性重涂到 `MechanismCells`（**边界改变自动贴边**，被玩家挡住跳过的格不会误显示；**满级后每次生长仍刷新**补齐已空出的格）。**出场动画**：范围更新的新增占格（含进关初建）按 `terrain_mech.svg` 帧行 0→1→2 随 `grow_anim_sec` 播一次（`_pop_mech_cells`），随后停在完成帧 row2，与既有格外观一致。**核心格同样铺瓦**：铺瓦集合=全部 claimed 格（含核心），贴边掩码天然把核心算作生长体一部分，核心与生长体相邻角点不缺瓦；核心外观由 Core Sprite 绘制，Mechanism 根节点 `z_index=1` 浮在 MechanismCells 层之上（该层在场景树位于 EntityRoot 之后，不抬层级 Core 会被瓦片盖住）。

### 4.5 输入锁（机关生长动画）
- 机关生长动画期间锁移动输入（≤0.3s）：`input_locked=true`，`Level._unhandled_input` 忽略移动输入；`restart`(R) 始终可用。
- Esc 使用 `ui_cancel` 打开局内暂停菜单（继续/重开/退出）；暂停菜单由 `LevelHUD.tscn` 场景树定义，打开时暂停 SceneTree，再次按 Esc 或点击继续恢复。

## 5. 数据定义与数值配置

### 5.1 通用规则
- **关卡布局不做成数据文件**：关卡 = 场景直编（§4.4）。
- 唯一 `.tres` 数据 = 全局数值 `Resources/Config/Balance.tres`（类 `Balance`，`@export`，可 Inspector 直接调）。
- 自定义资源/数据类脚本放 `Scripts/Data/`（`Balance.gd`、`MechanicShapes.gd`、`GridMetrics.gd`），`class_name` PascalCase 与文件同名。

### 5.2 关卡场景导出字段（权威，Level.gd）
| 导出 | 类型 | 说明 |
|------|------|------|
| `level_id` | int | 唯一编号（LevelSelect 排序/记录步数用） |
| `level_name` | String | 关卡内部描述名（选关界面仅显示 `level_id`） |
| `map_size` | Vector2i | **仅当场景完全空白时的保底网格**（默认 32×32）；一旦涂了地板/放了实体，地图范围=内容外接矩形（涂格+实体），机关只能在该范围内生长 |
| `initial_max_len_override` | int | 0=沿用全局 Balance 的初始 L；>0 本关覆盖 |
| `food_len_gain_override` | int | 0=沿用全局 ΔL；>0 本关覆盖 |
| `mechanism_max_level_override` | int | 0=沿用全局机关最高阶段；>0 本关覆盖（钳制 0–4） |
| `growth_step_interval_override` | int | 0=沿用全局生长周期；>0 本关覆盖 |

> 上述 4 个 `*_override` 属「本关数值」组（Inspector 里一目了然），**`grow_anim_sec` 只在全局 Balance，关卡不导出**。
> 实体子节点（PlayerSpawn/Food/Goal/Mechanism）均导出 `cell: Vector2i`；Mechanism 另导出 `initial_level`。障碍不是实体，由 `Obstacles` 层涂格定义。

### 5.3 机关生长（实现层事实，源自玩法规则）
- 阶段 `lv ∈ [0, cap]`（cap 默认 4），形状含中心、逐级嵌套（**权威表见 [功能需求文档](design/功能需求文档.md) §4.2.1**）；关卡启动注入 `Mechanism.level_cap`（本关 override 或全局）。
- 逻辑占格 `Mechanism.claimed`（只增不减）：每次生长 `claim_missing(blocked)`，blocked=玩家身体+起点+终点（保护格）。**满级后每次生长仍调用刷新**——此前被身体挡住、现已空出的 shape 格会被补占，阶段维持最高。
- **占格即时生效**：生长当帧更新 `GridSystem.mech_cells`，动画 ≤0.3s 锁输入，动画后跑死局检查。
- 机关渲染：生长体占格（**含核心格**）同步到关卡 `MechanismCells` TileMapLayer 确定性贴边；核心外观=Core 贴图（Mechanism 根节点 `z_index=1` 浮于瓦片层之上）。无 Stage 预览场景。

### 5.4 进度存档（SaveManager）
- Autoload `SaveManager`（`Scripts/Autoload/SaveManager.gd`），文件 `user://growth_save.cfg`（ConfigFile）。
- 内容：`best_steps`（Dictionary `level_<id>` → 步数）。
- 接口：`record_result(level_key, steps)` / `best_steps_for(key)`。
- 胜利时记录；测试期全开、不做关卡锁定。

### 5.5 数值配置（Balance.tres）
- 文件 `Resources/Config/Balance.tres`（类 `Scripts/Data/Balance.gd`），放**全局基准数值**（`@export`）：
  `initial_max_len=3`、`food_len_gain=2`、`mechanism_max_level=4`、`growth_step_interval=6`、`grow_anim_sec=0.3`。
- **单关覆盖**：`initial_max_len/food_len_gain/mechanism_max_level/growth_step_interval` 可在每个关卡 Level 根节点以 `*_override>0` 覆盖（0=沿用全局）；`grow_anim_sec` 仅全局，不进关卡。
- 运行入口：`GameManager.balance` 只读；脚本不得硬编码数值；**数值权威清单见 [功能需求文档](design/功能需求文档.md) §7**。

### 5.6 测试基准数值（QA 回归速查，权威出处=功能需求 §7）
| 项 | 基准 | 说明 |
|----|------|------|
| 网格 | 默认 32×32 | 运行时自动扩到实体覆盖范围 |
| 初始最大身长 L | 3 | HUD 显示 L；trail 长度硬上限 ≤ L，S→head 连续 |
| 食物加长 | +2/个 | 仅增 L，不触发机关 |
| 机关形状 | 中心恒占；lv0–4 总占 1/5/9/13/21 | 去中心 0/4/8/12/20（权威表见功能需求 §4.2.1） |
| 生长节奏 | 默认每 6 有效步 → 全体机关生长 1 次 | 该关可 override；未满级+1、满级刷新；占格即时生效；动画 ≤0.3s 锁输入 |
| 步数计数 | 仅有效移动/截断 +1 | 无效移动不计步；身长达 L 前进空格被禁（不计步） |
| 胜负 | 踏入终点=胜；BFS 无通路=败 | BFS 忽略身长与身体（保护格=起点/终点不占） |
| 关卡/解锁 | 场景直编 `Level_*.tscn`；测试期全开 | LevelSelect 自动扫描（排除模板） |
