## 1. 项目概述

### 1.1 目标
在 GameJam 时限内交付一款以 **Grow（生长）** 为核心机制的可玩原型，强调手感清晰、循环闭环、扩展友好。架构优先考虑"快速决策 → 快速落地"。

### 1.2 技术栈
| 项 | 选择 |
|----|------|
| 引擎 | Godot 4.7（stable mono / 标准版均可，本项目用 GDScript 不依赖 mono） |
| 语言 | GDScript（单一语言，避免混用） |
| 渲染 | Forward+，Windows 下 RenderingDevice 驱动 = d3d12 |
| 物理 3D | Jolt Physics |
| 2D 拉伸 | `canvas_items` / `expand` |
| VCS | Git + Git LFS，远端 `github.com/YICIYUAN-GAME-DEPARTMENT/Growth` |

### 1.3 里程碑（建议，按 GameJam 时限自定）
- M0 架构与规范（本文件 + autoload + Main）✅
- M1 玩法原型竖切（一个可玩场景，核心循环跑通）
- M2 内容铺量（关卡/数值/美术/音频）
- M3 打磨与导出

## 2. 架构设计

详见 [docs/architecture/架构说明.md](architecture/架构说明.md)。要点：

### 2.1 分层
```
┌─────────────────────────────────────────┐
│ Autoload 单例（全局）                     │  GameManager / EventManager
│                                         │  ResourceManager / AudioManager
├─────────────────────────────────────────┤
│ Systems（系统层，按玩法组装）              │  如 CombatSystem / GrowthSystem
├─────────────────────────────────────────┤
│ Entities（实体层）                        │  Player / Enemy / Pickup …
├─────────────────────────────────────────┤
│ Scenes（场景层，编排上述组件）             │  Main → Levels / Menus
├─────────────────────────────────────────┤
│ Resources（数据/配置层）                  │  .tres / .json 定义
└─────────────────────────────────────────┘
```

### 2.2 通信原则
- **跨系统通信用信号**，统一走 `EventManager.*`，禁止互相 `get_node("/root/...")` 硬引用。
- **资源获取走** `ResourceManager.get_scene(id)` / `get_resource(id)`，禁止裸 `load()` 散落各处。
- **音频走** `AudioManager.play_sfx/play_music`，禁止业务代码自建 `AudioStreamPlayer`。
- **场景流转走** `GameManager.change_scene()` / `GameScene.exit_to()`，禁止裸 `change_scene`。

### 2.3 玩法扩展点
玩法冻结后新增内容请挂到这些扩展点，**不要改动 autoload 的公共接口**：
- 新增系统 → `Scripts/Systems/<Xxx>System.gd`，由场景持有。
- 新增实体 → `Scripts/Entities/<Xxx>.gd` 继承基类。
- 新增信号 → 在 `EventManager` 末尾"Grow 主题 Hook"区追加。
- 新增资源类型 → `Resources/<Category>/` 新建目录并在 §3.4 登记。

## 3. 资源制作与导入规范

### 3.1 总则
- 所有资源放 `res://` 下对应目录，**禁止散落根目录**。
- 大二进制资源走 Git LFS（§3.8）；文本类（`.gd/.tscn/.tres/.cfg`）永不入 LFS。
- 新资源必须登记进 §3.9 资产清单，避免重复制作。

### 3.2 贴图导入设置
| 用途 | 建议设置 |
|------|---------|
| 角色/精灵 | Lossy + Mipmap Off（2D）/ On（3D），HDR Off |
| UI | Lossless，Mipmap Off，`filter=false`（像素 UI）或 `true`（高清 UI） |
| 背景 | Lossy，Mipmap On |
| 法线/ HDR | 视情况 Lossless |

未定规格的先以默认导入，并在 §3.9 标注【待定】。

### 3.3 命名规范
统一格式：`<前缀>_<类型>_<名称>_<版本>`，全大写下划线，禁止中文与空格。

| 前缀 | 含义 | 示例 |
|------|------|------|
| `CHR` | 角色 | `CHR_Player_Base_01` |
| `ENM` | 敌人 | `ENM_Slime_Green_01` |
| `SKL` | 技能 | `SKL_Player_Fireball_01` |
| `PSV` | 被动 | `PSV_Thorn_Spike_01` |
| `CRD` | 卡牌（若采用卡牌玩法） | `CRD_Attack_QuickStrike_01` |
| `LVL` | 关卡 | `LVL_Forest_01` |
| `SCN` | 通用场景 | `SCN_MainMenu_01` |
| `SFX` | 音效 | `SFX_UI_Click_01` |
| `MUS` | 音乐 | `MUS_Forest_Loop_01` |
| `ART` | 美术 | `ART_BG_Forest_Day_01` |

版本号两位递增，重大改动 +1 主版本。

### 3.4 目录职责
| 目录 | 放什么 | 不放什么 |
|------|--------|---------|
| `Resources/Cards/` | 卡牌定义（若启用卡牌） | 美术 |
| `Resources/Enemies/` | 敌人定义 | 行为脚本 |
| `Resources/Skills/` | 技能定义 | — |
| `Resources/Passives/` | 被动定义 | — |
| `Resources/Characters/` | 角色定义 | — |
| `Resources/Config/` | 全局平衡 / 数值表 | — |
| `Art/Sprites/` `Art/Backgrounds/` `Art/UI/` `Art/Effects/` | 美术 | 脚本 |
| `Audio/SFX/` `Audio/Music/` | 音频 | — |
| `Scenes/` `Scenes/Levels/` `Scenes/UI/` `Scenes/Entities/` | 场景 | 数据 |
| `Scripts/` | 脚本 | 二进制 |
| `UI/Theme/` `UI/Fonts/` | UI 主题与字体 | — |
| `Models/` | 3D 模型（若使用） | — |

### 3.5 音频导入
- 优先 **Ogg**（BGM）/ **Wav**（短 SFX）；少用 mp3。
- SFX：`loop=false`；BGM：`loop=true`。
- 总线：`Master → Music / SFX`，UI 音走 SFX 总线。

### 3.6 字体
- `.ttf/.otf` 入 LFS；SDF 字体按需开启。

### 3.7 占位资源
未定稿美术用纯色/线框占位，命名加 `_TMP` 后缀，正式替换后删除占位并在 §3.9 更新编号。

### 3.8 Git LFS 规则
- `.gitattributes` 已按扩展名追踪：`png/jpg/webp/bmp/tga/psd/kra/aseprite/glb/gltf/fbx/obj/wav/ogg/mp3/flac/ttf/otf/ogv/mp4/zip`。
- **大资源**（> ~500KB 或上述类型）自动入 LFS，无需手动操作；提交信息 `asset` 类型并注明资产编号（A-xx，见 §3.9）。
- **禁止** LFS 追踪 `.gd/.tscn/.tres/.cfg/.import` 等文本。
- 提交流程见 [docs/agents/rules/collaboration-rules.md](agents/rules/collaboration-rules.md) §资源入库。

## 4. 场景与节点组织

### 4.1 通用约定
- 场景根节点继承 `GameScene`（玩法场景）或 `Control`（UI 场景）。
- 节点名用 PascalCase（`WorldRoot`），变量名用 snake_case（`world_root`）。
- `@onready` 缓存节点引用，**禁止**在 `_process` 里反复 `get_node`。
- 信号连接在 `_ready()` 顶部集中声明，方便审查。

### 4.2 目录与编排（呼应 §3.4）
- `Scenes/Main.tscn`：根场景，持有 `WorldRoot`（Node2D）+ `UIRoot`（CanvasLayer）。
- `Scenes/Levels/`：玩法场景（继承 `GameScene`）。
- `Scenes/UI/`：菜单/HUD/Pause 等纯 UI 场景或预制。
- `Scenes/Entities/`：实体预制体（Player/Enemy/Pickup）。

### 4.3 Main.tscn 节点树
```
Main (Node2D, Main.gd)
├── WorldRoot (Node2D)        ← 玩法场景实例化挂这里
└── UIRoot (CanvasLayer)      ← HUD/暂停覆盖层挂这里
```

### 4.4 暂停规则
- 统一走 `GameManager.pause_game()/resume_game()`，由 `Main.gd` 监听 `pause` 动作触发。
- 暂停覆盖层在 `UIRoot` 下，`process_mode = PROCESS_MODE_WHEN_PAUSED`。

## 5. 数据定义（Resource / JSON）

> **状态：占位模板。** Grow 玩法冻结后，本节字段需团队评审定稿。当前字段集参考常见类型化结构，便于 AI 智能体与成员对齐"一个定义文件长什么样"。

### 5.1 通用规则
- 配置数据用 Godot `Resource`（`.tres`）或 JSON 二选一：**少量、需编辑器预览**用 Resource；**大量、程序生成**用 JSON。
- 所有定义类继承 `Resource`，类名 = PascalCase，文件名 = 定义名。
- ID 字段命名 `XxxIdentityID`（如 `CardIdentityID`），值用整数避免重命名爆炸。

### 5.2 字段规范（示例模板，玩法冻结后调整）

**CardDefinition**（若采用卡牌机制）
| 字段 | 类型 | 说明 |
|------|------|------|
| `CardIdentityID` | int | 全局唯一编号 |
| `InternalName` | String | 人类可读名 |
| `CardType` | Enum | 攻击/技能/防御… |
| `EnergyCost` | int | 能量消耗 |
| `EffectType` | Enum | 伤害/治疗/增益… |
| `EffectValue` | int | 主数值 |
| `Slots` | Array[int] | 槽位标签 |
| `Tags` | Array[StringName] | 机制标签 |

**EnemyDefinition**
| 字段 | 类型 | 说明 |
|------|------|------|
| `EnemyIdentityID` | int | 唯一编号 |
| `BaseMaxHP` | int | 基础血量 |
| `BaseSpeed` | int | 基础速度 |
| `DeckComposition` | Array | 行动池（若用卡牌 AI） |
| `IntentCycle` | Array | 意图循环链表 |

> 若 Grow 玩法不采用卡牌/意图机制（例如改为"植物生长 sim"），上述模板替换为对应实体定义（`PlantDefinition`/`StageDefinition` 等），章节编号不变。

### 5.3 …（其他定义类，按需补充 Skill / Passive / Character）

### 5.4 资源注册
定义 `.tres` 后，在 `MainMenu._ready()` 或专用 `BootStrap` 中调用：
```gdscript
ResourceManager.register_resource("slime_green", "res://Resources/Enemies/ENM_Slime_Green_01.tres")
```

### 5.5 平衡表
- 全局数值放 `Resources/Config/Balance.tres` 或 `balance.json`，禁止硬编码在脚本里。
