## 1. 项目概述

### 1.1 目标
在 GameJam 时限内交付 **2D 俯视网格解谜游戏（Growth，暂定代号 "绳蛇解谜"）** 的可玩原型并打磨导出。核心机制：主角身长受限、机关随步数生长挤压空间、规划路线进入终点。强调循环清晰、可推演、扩展友好。

### 1.2 技术栈
| 项 | 选择 | 说明 |
|----|------|------|
| 引擎 | Godot 4.7 stable（标准版） | GDScript，不依赖 mono |
| 语言 | GDScript | 单语言，不混 C# |
| 渲染 | Forward+ | Windows RenderingDevice = d3d12 |
| 2D 拉伸 | `canvas_items` / `expand` | 保证任意窗口比例无黑边 |
| 输入 | 内置 `[input]` 动作 | WASD 移动 + `restart`(R) + `pause` |
| 存档 | `user://` | 解锁进度 / 步数记录（见 §5.4） |
| VCS | Git + Git LFS | 远端 `github.com/YICIYUAN-GAME-DEPARTMENT/Growth` |

### 1.3 里程碑
- **M0 工程与规范**：架构、本文档、功能需求文档、环境、AGENTS/技能 —— ✅（本次）
- **M1 可玩竖切**：主菜单→关卡1→移动/身长/食物/机关生长/BFS死局判定→胜负
- **M2 内容铺量**：8 关数据 + 关卡选择 + 进度存档 + 占位美术打磨
- **M3 打磨导出**：平衡、音效、教程文案、导出（含 LFS 完整性检查）

## 2. 架构设计

> 详细分层、Autoload 接口、事件总线说明见 [docs/architecture/架构说明.md](architecture/架构说明.md)（本文 §2 为其概要权威）。

### 2.1 分层
```
Autoload 单例（全局，跨场景存活）        GameManager / EventManager / ResourceManager / AudioManager / SaveManager
  ↓
Systems（玩法系统，由关卡场景持有）       GridSystem（网格+BFS死局判定）/ MechanismSystem / LevelState
  ↓
Entities（实体层，挂关卡 World/EntityRoot）Player(主角) / Mechanism(机关) / Food(食物) / Goal(终点)
  ↓
Scenes（编排层）                        Main / UI(MainMenu·LevelSelect·HUD·Overlay) / 关卡场景
  ↓
Resources（数据层）                      LevelDefinition(.tres) / Balance(.tres)
```

**依赖方向：** Autoload ← Systems ← Entities ← Scenes ← Resources。禁止反向依赖。

### 2.2 通信原则
- 跨系统通信用信号，统一走 `EventManager.*`；禁止 `get_node("/root/OtherSystem")` 硬引用。
- 资源获取走 `ResourceManager.get_scene(id)` / `get_resource(id)`；禁止裸 `load()` 散落。
- 音频走 `AudioManager.play_sfx/play_music`；禁止业务代码自建 `AudioStreamPlayer`。
- 场景流转走 `GameManager.change_scene()` / `GameScene.exit_to()`；禁止裸 `change_scene`。
- **全局数值与关卡规则唯一来源：** `Balance.tres` / 关卡 `.tres`（§5）+ [功能需求文档](design/功能需求文档.md)。脚本内禁止硬编码玩法数值。

### 2.3 扩展点（玩法新增/修改的接法）
- 新增系统 → `Scripts/Systems/<Xxx>System.gd`，由关卡场景持有（不进 Autoload）。
- 新增实体 → `Scripts/Entities/<Xxx>/` 目录 + `Scenes/Entities/<Xxx>.tscn` 预制。
- 新增关卡 → `Resources/Levels/LVL_*.tres`（LevelDefinition），登记进 `SaveManager` 关卡清单。
- 修改数值 → 只改 `Balance.tres` / 关卡 `.tres`；规则性变更需改 [功能需求文档](design/功能需求文档.md) 并走 PR。
- 新增全局信号 → 追加到 `EventManager` 末尾 `## Gameplay` 区块；**勿删改既有信号签名**。

## 3. 资源与命名规范

### 3.1 总则
- 资源放 `res://` 对应目录，禁止散落根目录。
- 文本类（`.gd/.tscn/.tres/.cfg/.import`）永不入 LFS；大二进制（图/音频/模型）走 LFS（§3.8）。
- 新增美术/音频资源必须登记进 §3.9 资产清单，避免重复制作。

### 3.2 图片/贴图导入
| 用途 | 建议设置 |
|------|---------|
| TileSet 网格底图 / 障碍 / 机关占格 | 关闭 Mipmap、`filter=false`（像素感）或 `true`（高清），按最终美术决定 |
| 角色/机关/食物/终点精灵 | Lossy，Mipmap Off，HDR Off |
| UI | Lossless，Mipmap Off |

未定规格先默认导入，并在 §3.9 标注【待定】。

### 3.3 命名规范
统一格式：`<前缀>_<名称>_<序号>`，全大写下划线；资源文件禁止中文与空格。

| 前缀 | 含义 | 示例 |
|------|------|------|
| `LVL` | 关卡定义 `.tres` | `LVL_01_Tutorial.tres` |
| `CHR` | 主角/机关/食物/终点等实体场景或贴图 | `CHR_Player_Head_01`、`CHR_Mech_Stage_03` |
| `TILE` | TileSet 底图/障碍图块 | `TILE_Floor_01`、`TILE_Wall_01` |
| `UI` | HUD 图标/按钮 | `UI_Btn_Restart_01` |
| `SFX` | 音效 | `SFX_Food_Eat_01`、`SFX_Mech_Grow_01` |
| `MUS` | 音乐 | `MUS_Puzzle_Amb_01` |

- 脚本 `.gd` / 场景 `.tscn`：`PascalCase`（与 `class_name` 一致），见 [coding-rules](agents/rules/coding-rules.md)。
- 版本号两位递增，重大改动 +1。

### 3.4 目录职责
| 目录 | 放什么 | 不放什么 |
|------|--------|---------|
| `Scenes/` `Scenes/Levels/` `Scenes/UI/` `Scenes/Entities/` | 场景/预制 | 数据、二进制美术 |
| `Scripts/` `Scripts/Autoload/` `Scripts/Core/` `Scripts/Systems/` `Scripts/Entities/` `Scripts/UI/` `Scripts/Data/` `Scripts/Utils/` | GDScript | 二进制 |
| `Resources/Levels/` | LevelDefinition `.tres` | — |
| `Resources/Config/` | `Balance.tres` 等全局配置 | — |
| `Art/Sprites/` `Art/Tiles/` `Art/UI/` | 美术 | 脚本/数据 |
| `Audio/SFX/` `Audio/Music/` | 音频 | — |
| `UI/Theme/` `UI/Fonts/` | 主题/字体 | — |
| `docs/` | 权威文档/技能/规则 | — |

### 3.5 音频导入
- BGM 用 Ogg（可循环），SFX 用 Wav；少用 mp3。
- SFX `loop=false`；BGM `loop=true`。
- 总线：`Master → Music / SFX`，UI 音走 SFX。

### 3.6 字体
- `.ttf/.otf` 入 LFS；系统默认字体可在原型期直接使用。

### 3.7 占位资源
- 未定稿美术用纯色矩形/线框占位：命名加 `_TMP` 后缀，正式替换后删除占位并在 §3.9 更新。
- 占位资源同样登记 §3.9，状态标【待定】。

### 3.8 Git LFS 规则
- `.gitattributes` 已按扩展名追踪：`png/jpg/jpeg/webp/bmp/tga/psd/kra/aseprite/glb/gltf/fbx/obj/wav/ogg/mp3/flac/ttf/otf/ogv/mp4/zip`。
- 大资源（>~500KB 或上述类型）自动入 LFS；提交信息用 `asset` 前缀并注明 A-xx 资产编号。
- 禁止 LFS 追踪 `.gd/.tscn/.tres/.cfg/.import`。
- 入库流程见 [collaboration-rules §4](agents/rules/collaboration-rules.md)。

### 3.9 资产清单（A-xx 编号）
> 新增资源在此登记；AI 智能体制作前先查此表。**仅登记美术/音频/关卡数据等"资产"**；代码场景/脚本不登记。

| 编号 | 名称 | 路径 | 类型 | 状态 | 备注 |
|------|------|------|------|------|------|
| A-01 | 项目图标 | `res://icon.svg` | 2D | ✅ | 复用 Godot 默认亦可 |
| A-02 | 主角头部占位 | `res://Art/Sprites/CHR_Player_Head_01_TMP.png` | 2D | 【待定】 | 或纯色节点，无需资产 |
| A-03 | 机关占位 | `res://Art/Sprites/CHR_Mech_Stage_01_TMP.png` | 2D | 【待定】 | 可先画 5 阶段 |
| A-04 | 食物/终点占位 | `res://Art/Sprites/` | 2D | 【待定】 | — |

## 4. 场景与节点组织

### 4.1 通用约定
- 玩法场景根节点继承 `GameScene`（或 `LevelScene`）；UI 根为 `Control`。
- 节点名 PascalCase，变量名 snake_case；`@onready` 缓存节点，禁止在 `_process` 反复 `get_node`。
- 信号连接集中在 `_ready()` 顶部声明。
- 网格玩法不依赖物理碰撞：实体用节点/数据判定，TileMap 仅作底图渲染。

### 4.2 目录与编排（呼应 §3.4）
| 场景 | 职责 |
|------|------|
| `Scenes/Main.tscn` | 根场景：`WorldRoot` + `UIRoot`（CanvasLayer） |
| `Scenes/UI/MainMenu.tscn` | 主菜单（开始/退出） |
| `Scenes/UI/LevelSelect.tscn` | 关卡选择（线性解锁，来自 SaveManager） |
| `Scenes/Levels/Level.tscn` | 通用玩法场景，按 `LevelDefinition` 实例化关卡 |
| `Scenes/UI/HUD.tscn` | 身长/食物/步数/重开/退出（叠加于关卡之上） |
| `Scenes/Entities/*.tscn` | Player / Mechanism / Food / Goal 预制 |

### 4.3 Main.tscn 节点树
```
Main (Node2D, Main.gd)
├── WorldRoot (Node2D)        ← 当前场景实例（Menu / LevelSelect / Level）挂这里
└── UIRoot (CanvasLayer)      ← 全局覆盖层（暂停、通用转场）挂这里
```

### 4.4 关卡场景（Level.tscn）建议结构
```
Level (Node2D, LevelScene.gd extends GameScene)
├── Ground (TileMapLayer)        ← 底板 + 静态障碍（由 LevelDefinition 生成）
├── EntityRoot (Node2D)
│   ├── Goal    (Goal.tscn)
│   ├── Foods   (Node2D)          ← Food.tscn 实例
│   ├── Mechanisms (Node2D)       ← Mechanism.tscn 实例（5 阶段表现）
│   └── Player  (Player.tscn)
├── GridSystem (Node)             ← 网格状态 + 可走判定 + BFS
├── MechanismSystem (Node)        ← 机关占格/生长/播放动画/锁输入
└── HUDLayer (CanvasLayer)        ← HUD.tscn 实例（也可经 EventManager 挂到 UIRoot）
```
关卡逻辑由 LevelDefinition 数据驱动，一个 `Level.tscn` 承载全部关卡。

### 4.5 暂停与输入锁
- 暂停：`GameManager.pause_game()`/`resume_game()`；暂停覆盖层 `process_mode = PROCESS_MODE_WHEN_PAUSED`。
- **机关生长动画期间输入锁**（≤0.3s）：由 MechanismSystem 设置 `input_locked`，Level 忽略移动输入。

## 5. 数据定义与数值配置

### 5.1 通用规则
- 配置数据统一用 Godot `Resource`（`.tres`），**本项目不采用 JSON**。
- 自定义资源类脚本放 `Scripts/Data/`，`class_name` PascalCase 且与文件同名（如 `LevelDefinition.gd`）。
- 资源 id（`ResourceManager` key）用 snake_case；`LevelDefinition.level_id` 用整数避免改名爆炸。

### 5.2 LevelDefinition 字段规范（权威）
文件：`Resources/Levels/LVL_*.tres`（类：`Scripts/Data/LevelDefinition.gd`）

| 字段 | 类型 | 说明 |
|------|------|------|
| `level_id` | int | 唯一编号（1–8，等于解锁顺序） |
| `display_name` | String | 关卡显示名（如 "教程 · 生长"） |
| `grid_size` | Vector2i | 网格宽高（默认 `(32,32)`） |
| `start_cell` | Vector2i | 主角起点（=尾部锚点 S） |
| `goal_cell` | Vector2i | 终点 E |
| `initial_max_len` | int | 初始最大身长 L（默认 3） |
| `obstacles` | Array[Vector2i] | 静态障碍格集合 |
| `foods` | Array[Vector2i] | 食物格集合 |
| `mechanisms` | Array[MechanismSpawn] | 机关出生点（center_cell + 初始阶段，见下） |
| `is_tutorial` | bool | 是否教程关（影响 HUD 提示/跳过确认文案） |

`MechanismSpawn`（内嵌子资源或 Dictionary）：`{ "center": Vector2i, "initial_level": int }`。机关生长形状/数值不存关卡里（见 §5.3），只在 `Balance`/`MechanismSystem` 统一。

> 机关默认初始阶段 `0`（中心 1 格）。教程关若要"开始时已扩张"，可用 `initial_level>0`。

### 5.3 机关生长（实现层事实，源自玩法规则）
- 阶段 `lv ∈ [0,4]`，形状含中心、逐级嵌套（**形状规则见 [功能需求文档](design/功能需求文档.md) §4.3 权威表**）。
- 生长事件由 `MechanismSystem` 统一在步数满足时触发；**占格 = 机关占据集合 `mech_cells`**，动画期间锁输入。
- 每格状态用 `GridSystem` 维护，机关集合参与"可走/BFS"判定（见功能需求 §4.6 死局判定）。

### 5.4 进度存档（SaveManager）
- Autoload `SaveManager`（`Scripts/Autoload/SaveManager.gd`），文件 `user://growth_save.cfg`（ConfigFile）。
- 内容：`highest_unlocked`（int，默认 1）、`steps`（Dictionary level_id→步数）、`foods_eaten`（可选）。
- 接口：`get_highest_unlocked()` / `unlock_level(id)` / `record_result(level_id, steps)`。
- 退出主界面 / 通关时保存；其余阶段不落盘。

### 5.5 数值配置（Balance.tres）
- 文件 `Resources/Config/Balance.tres`（类 `Scripts/Data/Balance.gd`），集中放全局数值：
  `initial_max_len=3`、`food_len_gain=2`、`mech_level_max=4`、`growth_step_interval=6`、`grow_anim_sec=0.3`、`cell_visual_size=...`（占位）。
- 修改只改 `.tres`，脚本不得硬编码数值；**数值权威清单见 [功能需求文档](design/功能需求文档.md) §7**。

### 5.6 测试基准数值（QA 回归速查，权威出处=功能需求 §7）
| 项 | 基准 | 说明 |
|----|------|------|
| 网格 | 32×32 | 可缩，>=起点距 |
| 初始最大身长 L | 3 | HUD 显示 L；实际身长 ≤ L |
| 食物加长 | +2/个 | 仅增 L，不触发机关 |
| 机关形状 | 中心恒占；lv0–4 总占 1/5/9/13/21 | 去中心 0/4/8/12/20（权威表见功能需求 §4.3） |
| 生长节奏 | 每 6 有效步 → 全体机关+1 阶段 | 截断也算；动画 ≤0.3s 锁输入 |
| 步数计数 | 仅有效移动/截断 +1 | 无效移动不计步（见功能需求 §4.2） |
| 胜负 | 踏入终点=胜；BFS 无通路=败 | BFS 忽略身长与身体 |
| 关卡/解锁 | 8 关（1–4 教程），线性解锁 | SaveManager |

## 7. 提交与协作

见 [docs/agents/rules/collaboration-rules.md](agents/rules/collaboration-rules.md) 与 [docs/agents/rules/coding-rules.md](agents/rules/coding-rules.md)。要点：
