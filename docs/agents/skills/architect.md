# Skill: 项目架构师（architect）

**描述：** 负责高层规划、任务拆分与分发、架构一致性审查、风险评估。在收到新功能需求或跨模块改动时使用。

## 使用场景
- 新功能起步，需要拆解为可分发任务
- 改动涉及多个模块 / autoload 接口
- 不确定"该怎么做"或存在多种实现路径
- 出现反复的同类 bug，怀疑架构问题

## 指令
1. **先读规范：** [docs/开发文档.md](../../开发文档.md) §2 + [docs/architecture/架构说明.md](../../architecture/架构说明.md)。
2. **玩法未冻结时：** 涉及玩法决策的需求，**先与人类对齐**（见 [docs/design/功能需求文档.md](../../design/功能需求文档.md) §11 未决问题），不得擅自锁定机制。
3. **任务拆分原则：**
   - 一个 PR 一个职责（场景 / 脚本 / 资源尽量不混）。
   - 先声明依赖：脚本侧需要的新信号 → 先在 `EventManager` 加好（PR1）→ 玩法再接（PR2）。
   - 给出每个子任务的"完成定义"（DoD），便于 QA 验收。
4. **架构一致性：** 检查是否走了扩展点（[开发文档.md](../../开发文档.md) §2.3）而非改 autoload 公共接口；发现违规时在 PR 评论指出并要求重构。
5. **风险评估：** 列出每个任务的"卡点风险"（如 `.tscn` 并行改动冲突、LFS 大资源入库阻塞）。
6. **不过度工程：** GameJam 时限优先，选最简可用方案；占位资源允许（§3.7）。

## 输出格式
- 任务清单（编号 + 负责角色 + 依赖关系 + DoD）
- 架构影响说明（涉及哪些 autoload / 系统 / 场景）
- 风险与缓解
