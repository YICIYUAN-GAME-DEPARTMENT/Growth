# 架构说明

> 配套主文档：[开发文档（权威）](../开发文档.md) §2。本文展开分层、Autoload、事件总线、场景编排等实现细节。
> 玩法规则与数值见 [功能需求文档（权威）](../design/功能需求文档.md)；本文件只讲"工程怎么搭"。

## 1. 分层职责

```
Autoload 单例（全局，跨场景存活）
   ├ GameManager      顶层状态/场景流转/暂停/胜负会话
   ├ EventManager     信号总线（解耦）
   ├ ResourceManager  场景与资源登记/缓存
   ├ AudioManager     BGM / SFX 播放
   └ SaveManager      解锁进度与步数存档（user://）
Systems（玩法系统，关卡场景持有）
   ├ GridSystem      网格状态 / 可走判定 / BFS 死局
   ├ MechanismSystem 机关阶段/占据集合/生长动画/输入锁
   └ LevelState      关卡状态编排（也可并入关卡脚本）
Entities（实体）
   ├ Player（头+轨迹）、Mechanism、Food、Goal（无 Enemy/卡牌类实体）
Scenes（编排层）
   ├ Main → UI(MainMenu/LevelSelect/HUD) / Level
Resources（数据层）
   ├ Resources/Levels/LVL_*.tres（LevelDefinition）
   └ Resources/Config/Balance.tres（全局数值）
```

**依赖方向：** Autoload ← Systems ← Entities ← Scenes ← Resources。**禁止反向依赖**：Autoload 不引用具体玩法类；Entities 不直接调 Systems（用信号）。

## 2. Autoload 单例

| 单例 | 文件 | 职责 | 对外接口（稳定，勿擅改） |
|------|------|------|--------------------------|
| `GameManager` | `Scripts/Autoload/GameManager.gd` | 顶层状态、场景切换、暂停、胜负会话 | `change_scene()` `pause_game()` `resume_game()` `start_level(level_id)` `end_game(result)` |
| `EventManager` | `Scripts/Autoload/EventManager.gd` | 全局信号总线（Gameplay 信号见 §3） | 各 `signal`（追加到文件尾 `## Gameplay` 区块） |
| `ResourceManager` | `Scripts/Autoload/ResourceManager.gd` | 场景/资源登记与缓存 | `register_scene()` `get_scene()` `register_resource()` `get_resource()` `prewarm()` |
| `AudioManager` | `Scripts/Autoload/AudioManager.gd` | BGM/SFX 播放 | `play_sfx()` `play_music()` `stop_music()` |
| `SaveManager` | `Scripts/Autoload/SaveManager.gd` | 解锁/步数存档 | `get_highest_unlocked()` `unlock_level()` `record_result()` `load()`/`save()` |

Autoload 在 `project.godot` `[autoload]` 段登记；代码直接以类名调用（如 `GameManager.start_level(1)`）。

## 3. 事件总线（Gameplay 信号）

在 `EventManager` 末尾 `## Gameplay` 区块声明；勿删改既有签名：

```gdscript
signal level_loaded(level_id: int)
signal player_moved(head: Vector2i)          # 每次有效移动/截断
signal max_length_changed(new_max: int)       # L 变化
signal move_count_changed(count: int)         # 步数变化
signal food_eaten(pos: Vector2i)
signal mechanism_grew(new_level: int)         # 全体机关同步 +1 后的阶段
signal input_locked(locked: bool)             # 机关动画期间
signal level_cleared(level_id: int, steps: int)
signal level_failed(level_id: int)
```

## 4. 资源管理

- 关卡 `.tres`（LevelDefinition）注册到 ResourceManager；`GridSystem`/关卡场景 `_setup()` 内 `register_resource("lvl_01", "res://Resources/Levels/LVL_01_*.tres")`。
- 大 BGM/贴图用 `prewarm()` 后台加载，使用前 `is_prewarmed()` 取回。

## 5. 场景编排

### 5.1 Main.tscn
根场景（节点树见主文档 §4.3）：`WorldRoot` 挂当前场景（Menu/LevelSelect/Level），`UIRoot` 挂全局覆盖层。玩法场景经 `ResourceManager.get_scene(id).instantiate()` 后入 `WorldRoot`。

### 5.2 GameScene 生命周期
```
_ready() → _setup() → _on_scene_entered()
... 运行 ...
exit_to(target) → _on_scene_exiting() → GameManager.change_scene()
```

### 5.3 关卡（Level.tscn）
- 单场景承载全部关卡：入参 `level_id` → 从 ResourceManager 取对应 `LevelDefinition` → `_setup()` 生成 Ground/Goal/Foods/Mechanisms/Player。
- GridSystem 持有静态障碍 + 机关占据集合 `mech_cells`，提供 `is_walkable()` 与 `has_path_to_goal()`。
- HUD 实例挂 `UIRoot`，通过信号刷新（不动关卡内部状态）。
- 胜利/失败面板：由 `GameManager.end_game()` 驱动，关卡自身只发 `level_cleared/level_failed`。

### 5.4 输入锁
机关生长动画期间 `input_locked=true`；`Level._unhandled_input` 忽略移动输入（按键丢弃，不排队）。

## 6. 输入
- 动作集中在 `project.godot` `[input]`：`move_up/down/left/right`、`restart`(R，需新增)、`pause`(Esc)、`ui_*`。
- 代码用 `Input.is_action_pressed("move_up")`，禁裸查键码。

## 7. 说明：本作不使用物理
- 网格解谜基于数据判定（GridSystem），TileMap 仅渲染；无需 RigidBody/Area 碰撞。此点取代旧模板的"物理层命名"章节。
