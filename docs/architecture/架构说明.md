# 架构说明

> 配套主文档：[开发文档（权威）](../开发文档.md) §2。本文展开分层、Autoload、事件总线、场景编排等实现细节。
> 玩法规则与数值见 [功能需求文档（权威）](../design/功能需求文档.md)；本文件只讲"工程怎么搭"。

## 1. 分层职责

```
Autoload 单例（全局，跨场景存活）
   ├ GameManager      顶层状态/场景切换；持有 balance（Balance.tres 只读）
   ├ EventManager     信号总线（解耦）
   └ SaveManager      每关最佳步数存档（user://）
关卡脚本（每关一个 Level_<nn>.tscn，挂 Level.gd）
   ├ 逻辑：trail / 步数 / 机关生长 / BFS 死局 / HUD
   └ 持有 GridSystem（纯数据：可走判定 + has_path）
实体（设计者直接摆进关卡场景/涂格的节点与图层）
   ├ Ground / Obstacles（TileMapLayer，涂格；障碍=被涂格，非实体）
   ├ PlayerSpawn / Food / Goal / Mechanism(核心贴图，CellEntity 基类)
   ├ MechanismCells / PlayerCells（TileMapLayer，运行时同步占格/身体）
Scenes（窗口级场景，change_scene 全屏切换）
   ├ Scenes/UI/MainMenu.tscn（入口） / LevelSelect.tscn（扫描关卡）
   └ Scenes/Levels/Level_<nn>.tscn
数据
   ├ Resources/Config/Balance.tres（全局数值，@export；无关卡 .tres——布局即场景）
```

**依赖方向：** Autoload ← 关卡 ← 实体 ← 场景。禁止反向依赖：Autoload 不引用具体玩法类；实体不直接调关卡内部（用信号）。

## 2. Autoload 单例

| 单例 | 文件 | 职责 | 对外接口（稳定，勿擅改） |
|------|------|------|--------------------------|
| `GameManager` | `Scripts/Autoload/GameManager.gd` | 顶层状态、场景切换、关卡入口 | `balance` `start_level(path)` `restart_level()` `change_scene()` `back_to_level_select()` `back_to_main_menu()` |
| `EventManager` | `Scripts/Autoload/EventManager.gd` | 全局信号总线（Gameplay 信号见 §3） | 各 `signal`（追加到文件 `## Gameplay` 区块并同步本表） |
| `SaveManager` | `Scripts/Autoload/SaveManager.gd` | 每关最佳步数存档 | `record_result(key, steps)` `best_steps_for(key)` |

> 曾存在 ResourceManager / AudioManager 两个 Autoload，因零调用已随 v1.7 精简移除（音频功能本版不实现，见 [功能需求](../design/功能需求文档.md) §5.5）。

Autoload 在 `project.godot` `[autoload]` 段登记；代码直接以类名调用（如 `GameManager.start_level("res://Scenes/Levels/Level_01.tscn")`）。

## 3. 事件总线（Gameplay 信号）

在 `EventManager` 的 `## Gameplay` 区块声明；勿删改仍在 emit 的信号签名（新增需同步本表）：

```gdscript
signal level_loaded(level_id: int)
signal player_moved(head: Vector2i)          # 每次有效移动/截断
signal max_length_changed(new_max: int)       # L 变化
signal move_count_changed(count: int)         # 步数变化
signal food_eaten(pos: Vector2i)
signal mechanism_grew(new_level: int)         # 全体机关 +1 后的阶段
signal input_locked(locked: bool)             # 机关动画期间
signal level_cleared(level_id: int, steps: int)
signal level_failed(level_id: int)
```

> 现状：Level 内 UI 刷新/胜负结算为直接调用（Level→HUD、SaveManager）；信号用于跨系统解耦与扩展预留，接入方订阅即可。

## 4. 数据

- `Balance.tres`（`Scripts/Data/Balance.gd`，@export）：全局基准数值数据；`GameManager._ready` 加载为 `GameManager.balance`。单关可在 Level 根节点用 `*_override>0` 覆盖 4 项玩法数值（0=沿用全局）。
- 机关形状/像素换算为静态类：`MechanicShapes`、`GridMetrics`；TileMap 贴图：`Ground/Obstacles/MechanismCells` → `TerrainFloor/Wall/Mech.tres`（16 变体 4 角自动贴边，规则见 [开发文档](../开发文档.md) §4.4），`PlayerCells` → `PlayerSnek.tres`（管道连接件 + 头/尾格端点半截瓦）；头/尾为独立 Sprite 贴图；实体单贴图 `Art/Sprites/*.svg`。
- 关卡没有 LevelDefinition `.tres`：布局 = 关卡场景内的实体节点（§5.3）。

## 5. 场景编排

### 5.1 入口与切换
`project.godot run/main_scene = Scenes/UI/MainMenu.tscn`。菜单/选关/关卡均为**完整独立场景**，用 `GameManager.change_scene()` 全屏切换（无持久根容器）。

### 5.2 LevelSelect
扫描 `res://Scenes/Levels` 下 `Level_*.tscn`（自动排除 `LevelTemplate.tscn`），按 `level_id` 排序列出（测试期全开）；点击调用 `GameManager.start_level(path)`。

### 5.3 关卡（场景直编，Level.gd）
- 每关一个场景文件，根节点挂 `Scripts/Systems/Level.gd`；实体子节点决定内容。
- 实体位置语义：导出 `cell: Vector2i`（节点 position = `GridMetrics.cell_center(cell)`）；编辑器拖动自动吸附（@tool，逻辑在 `CellEntity` 基类，Mechanism 继承之）。
- 运行时 `Level._ready`：递归扫描实体 → 计算地图范围（Ground/Obstacles 涂格 + 实体格的外接矩形；**完全空白才退回 map_size**）→ 布玩家 → 同步机关/玩家层 → 开始。
- World/Cam：脚本运行时**不移动、不缩放**；World 默认 (0,0)，Cam 位置由作者在编辑器摆放，编辑器所见即游戏所得。
- 机关：核心=Core 单贴图（`z_index=1` 浮于瓦片层）；逻辑占格 = `MechanicShapes` + `Mechanism.claimed`，由 `claim_missing(blocked)` 维护（blocked=玩家身体+起点+终点）；生长体占格（含核心格）同步到 `MechanismCells` 层确定性贴边。
- 渲染：Ground/Obstacles 由作者在 TileMap 涂格；机关生长体/玩家身体由脚本同步到 `MechanismCells`/`PlayerCells` 层；头/尾独立 Sprite 由 `PlayerFx` 承载；实体子节点画自身贴图。
- 胜负/结算：关卡本地面板；通过 `EventManager.level_cleared/failed`（现状直接调用）+ `SaveManager.record_result`。

### 5.4 输入锁
机关生长动画期间 `input_locked=true`；`Level._unhandled_input` 忽略移动输入（按键丢弃，不排队）；`restart`(R) 始终可用。本版无游戏暂停功能。

## 6. 输入
- 动作集中在 `project.godot` `[input]`：`move_up/down/left/right`、`restart`(R)、`ui_*`。
- 代码用 `Input.is_action_pressed("move_up")`，禁裸查键码。

## 7. 说明：本作不使用物理
- 网格解谜基于数据判定（GridSystem），渲染为 TileMap 瓦片/贴图；无需 RigidBody/Area 碰撞。
