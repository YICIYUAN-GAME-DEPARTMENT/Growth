# 架构说明

> 配套主文档：[开发文档（权威）](../开发文档.md) §2。本文展开分层、Autoload、事件总线、场景编排等实现细节。
> 玩法规则与数值见 [功能需求文档（权威）](../design/功能需求文档.md)；本文件只讲"工程怎么搭"。

## 1. 分层职责

```
Autoload 单例（全局，跨场景存活）
   ├ GameManager      顶层状态/场景切换/暂停；持有 balance（Balance.tres 只读）
   ├ EventManager     信号总线（解耦）
   ├ AudioManager     BGM / SFX 播放
   └ SaveManager      每关最佳步数存档（user://）
关卡脚本（每关一个 Level_<nn>.tscn，挂 Level.gd）
   ├ 逻辑：trail / 步数 / 机关生长 / BFS 死局 / HUD
   └ 持有 GridSystem（纯数据：可走判定 + has_path）
实体（设计者直接摆进关卡场景的节点）
   ├ PlayerSpawn（出生点 S） / Obstacle / Food / Goal / Mechanism（含 5 阶段子场景）
Scenes（窗口级场景，change_scene 全屏切换）
   ├ Scenes/UI/MainMenu.tscn（入口） / LevelSelect.tscn（扫描关卡）
   └ Scenes/Levels/Level_<nn>.tscn
数据
   ├ Resources/Config/Balance.tres（全局数值，@export；无关卡 .tres——布局即场景）
```

**依赖方向：** Autoload ← 关卡 ← 实体 ← 场景。禁止反向依赖：Autoload 不引用具体玩法类；实体不直接调关卡内部（用信号）。

## 2. Autoload 单例

| 单例 | 文件 | 职责 | 对外接口（稳定，勿擅改） |
|------|------|------|--------------------------|
| `GameManager` | `Scripts/Autoload/GameManager.gd` | 顶层状态、场景切换、暂停、关卡入口 | `balance` `start_level(path)` `restart_level()` `change_scene()` `pause_game()` `resume_game()` `back_to_level_select()` `back_to_main_menu()` |
| `EventManager` | `Scripts/Autoload/EventManager.gd` | 全局信号总线（Gameplay 信号见 §3） | 各 `signal`（追加到文件尾 `## Gameplay` 区块） |
| `ResourceManager` | `Scripts/Autoload/ResourceManager.gd` | 资源缓存（可选使用） | `register_*()` `get_*()` `prewarm()` |
| `AudioManager` | `Scripts/Autoload/AudioManager.gd` | BGM/SFX 播放 | `play_sfx()` `play_music()` `stop_music()` |
| `SaveManager` | `Scripts/Autoload/SaveManager.gd` | 每关最佳步数存档 | `record_result(key, steps)` `best_steps_for(key)` `has_cleared(key)` |

Autoload 在 `project.godot` `[autoload]` 段登记；代码直接以类名调用（如 `GameManager.start_level("res://Scenes/Levels/Level_01.tscn")`）。

## 3. 事件总线（Gameplay 信号）

在 `EventManager` 末尾 `## Gameplay` 区块声明；勿删改既有签名：

```gdscript
signal level_loaded(level_id: int)
signal player_moved(head: Vector2i)          # 每次有效移动/截断
signal max_length_changed(new_max: int)       # L 变化
signal move_count_changed(count: int)         # 步数变化
signal food_eaten(pos: Vector2i)
signal mechanism_grew(new_level: int)         # 全体机关 +1 后的阶段
signal input_locked(locked: bool)             # 机关动画期间
signal level_cleared(level_id: int, steps: int)
signal level_failed(level_id: int)
```

## 4. 数据

- `Balance.tres`（`Scripts/Data/Balance.gd`，@export）：唯一数值数据；`GameManager._ready` 加载为 `GameManager.balance`。
- 机关形状/像素换算为静态类：`MechanicShapes`、`GridMetrics`、配色 `Palette`（占位）。
- 关卡没有 LevelDefinition `.tres`：布局 = 关卡场景内的实体节点（§5.3）。

## 5. 场景编排

### 5.1 入口与切换
`project.godot run/main_scene = Scenes/UI/MainMenu.tscn`。菜单/选关/关卡均为**完整独立场景**，用 `GameManager.change_scene()` 全屏切换（无持久根容器）。

### 5.2 LevelSelect
扫描 `res://Scenes/Levels` 下 `Level_*.tscn`，按 `level_id` 排序列出（测试期全开）；点击调用 `GameManager.start_level(path)`。

### 5.3 关卡（场景直编，Level.gd）
- 每关一个场景文件，根节点挂 `Scripts/Systems/Level.gd`；实体子节点决定内容。
- 实体位置语义：导出 `cell: Vector2i`（`cell * GridMetrics.CELL_PX` 像素）；编辑器拖动自动吸附（@tool）。
- 运行时 `Level._ready`：递归扫描实体 → 计算地图范围（覆盖实体+机关最大扩展，保底 `map_size`）→ 布玩家 → 校验 → 开始。
- 机关：Mechanism.tscn 内含 5 个 Stage 子场景用于编辑器预览/按 lv 切换；逻辑占格 = `Mechanism.claimed`，由 `claim_missing(blocked)` 维护（blocked=玩家身体+起点+终点）。
- 渲染：Level `_draw` 画底格/机关实际占格/玩家身体；实体子节点画自身占位色块；HUD 为关卡运行时创建的 CanvasLayer。
- 胜负/结算：关卡本地面板，不发 `end_game`（保留通用接口）；通过 `EventManager.level_cleared/failed` + `SaveManager.record_result`。

### 5.4 输入锁
机关生长动画期间 `input_locked=true`；`Level._unhandled_input` 忽略移动输入（按键丢弃，不排队）；`restart`(R) 始终可用。

## 6. 输入
- 动作集中在 `project.godot` `[input]`：`move_up/down/left/right`、`restart`(R)、`pause`(Esc)、`ui_*`。
- 代码用 `Input.is_action_pressed("move_up")`，禁裸查键码。

## 7. 说明：本作不使用物理
- 网格解谜基于数据判定（GridSystem），渲染为占位色块（后期可换 TileSet/贴图）；无需 RigidBody/Area 碰撞。
