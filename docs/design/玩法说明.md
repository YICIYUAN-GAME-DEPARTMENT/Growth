## 0. 一句话概念

> 主角的尾巴钉死在起点，身体像绳子一样延伸到头部；吃食物让最大身长增长（能去更远），但玩家每走 6 步，场上所有"生长机关"同步扩张一次（堵死更多格子）。玩家可以踏回自己的身体"擦写"轨迹重新规划，但在"够得着终点"与"路被机关堵死"之间找到那条解。

核心张力：**扩张可达范围 ↔ 机关随步数扩张切断通路**。

## 4. 主角与移动规则（核心）

### 4.1 主角模型
- **尾部**：固定在**起点格 `S`**，整个关卡内不变。
- **头部**：玩家操控的位置，初始也在 `S`（关卡开始身体仅 1 格）。
- **轨迹队列 `trail`**：玩家移动轨迹，`[S, ..., head]`，从尾到头排列。
- **身体**：= `trail`（身体就是轨迹本身，贪吃蛇式蜿蜒）。
- **最大身长 `L`**：初始 **3**，吃食物 **+2**。**信息框显示的是 L**。
- **实际身长**：= `len(trail)`，可 ≤ L（截断后减小，重新走出可增长到 L）。

### 4.2 移动规则
玩家按 WASD → 头部尝试移向相邻格 `N`（上下左右，禁斜走）。

**情况 A：`N` 是空地/食物/终点格**
1. **合法性判定**（必须全满足）：
   1. `N` 在 32×32 内；
   2. `N` 不是障碍物；
   3. `N` 不是机关占据格（含中心格，见 §5.4）；
   4. `N` 不是自身身体格（即 `N` 不在 `trail` 中）。
2. 判定通过 → 头部移到 `N`，`trail` 入队 `N`。
3. **长度约束**：若 `len(trail) > L`，弹出 `trail[1]`（尾后第一格，**保留 `trail[0] = S`**）。
4. 若 `N` 是食物格 → 触发吃食物（§6）。
5. 若 `N` 是终点格 → 胜利（§9）。

**情况 B：`N` 是自身身体格（即在 `trail` 中）**
1. **截断规则**：头部移到 `N`，`trail` 截断为 `trail[0 : index(N)+1]`，即从 `N` 之后的部分全部撤销。
2. 实际身长变为 `index(N)+1`（≤ L）。
3. 此操作允许玩家**擦写轨迹**重新规划路线（关键解谜机制）。
4. 截断也算 1 次行动（计入步数，见 §5.5）。
5. 截断后若 `N` 同时是食物格？—— 不可能（食物格走过即消失，不会留在 `trail`）。

> 注：踏入 `trail[0] = S`（起点）也允许，等于"完全回起点重开身体"，实际身长变 1。

### 4.3 活动范围受限（设计意图）
- `L` 限制 `trail` 长度 → 头部能走的最长路径 ≤ L。
- 走弯路消耗身长，可达范围收缩；走直线可达最远。
- 吃食物增加 L → 扩展可达范围（"Grow"主题核心动词之一）。
- 截断可回收身长，重新规划，避免卡死挫败。

## 5. 机关与生长机制（核心）

### 5.1 机关定义
- 关卡内有 **0 到多个**机关，各自独立维护阶段 `lv ∈ {0,1,2,3,4}`。
- 每个机关有**中心格 `C`**，生长形状以 `C` 为锚。
- **机关中心格 `C` 永远占据**（A 方案），主角不可踏入。
- 机关占据格子集合 = `{C} ∪ shape(lv)`（含中心），**占据格 = 障碍格**。
- 多个机关占据格重叠按并集（不叠加生长）。

### 5.2 生长触发（步数驱动）
- 维护**步数计数器 `move_count`**：每按一次移动键 +1（无论情况 A 还是 B，截断也算）。
- 当 `move_count` 达到 6 的倍数（即 `move_count % 6 == 0` 且 `move_count > 0`）时，**所有机关各 +1 阶段**（上限 Lv4，到顶不再长）。
- 生长是即时、同步、不可逆的。
- 生长动画**阻塞玩家输入**（动画结束前不接受移动；建议动画时长 ≤ 0.3 秒，避免拖节奏）。

### 5.3 生长形状表（总占据含中心，已调整为 A 方案）

| Lv | 总占据格数 | 扩散区格数(不含中心) | 形状描述 | 示意图（C=中心，X=占据） |
|----|-----------|---------------------|---------|--------------------------|
| 0 | 1 | 0 | 仅中心 | `C` |
| 1 | 5 | 4 | 中心+十字(上下左右) | `·X·` / `XCX` / `·X·` |
| 2 | 9 | 8 | 3×3 方块 | `XXX` / `XCX` / `XXX` |
| 3 | 13 | 12 | 5×5 菱形(曼哈顿≤2) | 菱形 |
| 4 | 21 | 20 | 5×5 方块去 4 角 | 25−4=21 |

> 总占据序列 **1/5/9/13/21**。扩散区（不含中心）= 0/4/8/12/20，对应原设计确认数字。

### 5.4 机关中心格
- **永远占据**，主角不可踏入（移动判定 §4.2 情况 A 第 3 条）。
- 视觉上为机关"核心"，生长从此向外扩张。

### 5.5 占格冲突处理（玩家身体阻挡生长）
- 机关生长时，`shape(lv)` 计算出的新占据格，若**被玩家身体（`trail`）占据**，则：
  - 该格**本次不被机关占据**（保留给玩家）；
  - 但机关 `lv` **仍然 +1**（生长等级提升不可逆）。
- **下次生长时**（`move_count` 再到 6 的倍数），`shape(lv+1)` 重新计算：
  - 若该格在新 shape 内且玩家已离开 → 占据；
  - 若该格在新 shape 内但玩家仍占 → 继续跳过；
  - 若该格不在新 shape 内 → 永远不占（错过）。
- BFS 失败检测时，被跳过的格子不计为机关障碍（玩家可走）。

### 5.6 生长可视化
- 生长瞬间播放扩张动画（缩放/淡入 + 粒子），时长 ≤ 0.3 秒，期间锁输入。
- 占据格用机关贴图覆盖（暂用纯色占位），未占据格用底图。

## 6. 食物与身长

| 项 | 值 |
|----|----|
| 每关食物数 | 关卡数据决定（建议 2–6） |
| 吃食物效果 | **最大身长 L +2**；该食物消失；**不触发机关生长** |
| 食物位置 | 关卡数据预设，固定不动 |
| 食物可视 | 闪烁/浮动动画（暂用纯色圆点占位） |
| 是否重生 | 否（吃完即完） |

> 吃食物是**纯增益**：扩展可达范围，无代价。但食物位置可能偏离最短路径，玩家需权衡"绕路吃食物" vs "直接冲终点（但 L 可能不够）"。机关生长由步数独立驱动，与食物无关。

## 7. 失败检测（系统自动）

### 7.1 触发时机
- **每次玩家移动后**（无论情况 A 还是 B，截断也算）；
- **每次机关生长完成后**。

### 7.2 检测规则
- 系统运行 BFS：
  - 起点：头部当前位置；
  - 终点：关卡终点格 `E`；
  - 障碍：障碍物格 + 机关占据格（**不含被玩家占而跳过的格**，见 §5.5）；
  - **不考虑身长、不考虑自身身体**（即假设玩家可无限延伸、身体可让出格子）。
- 若 BFS 找不到通路 → **当前局面无解 → 判定失败**，弹出失败界面。

### 7.3 设计意图
- 避免玩家陷入"已经无解却不知、继续空转"的挫败。
- 检测的是"地图静态布局是否还有通路"，与玩家操作无关，公平且可推演。
- 玩家可自行推演（高玩体验），也可依赖系统提示（休闲体验）。

### 7.4 实现要点
- BFS 在 `Scripts/Systems/GridSystem.gd` 内实现，暴露 `has_path_to_goal(head_pos) -> bool`。
- 32×32=1024 格，BFS 单次 < 1ms，无性能压力。

## 8. 游戏循环

```
关卡加载
  ├ 显示地图 / 实体 / HUD（L=3、食物数、步数=0）
  └ 头部在起点 S，trail=[S]
            │
            ▼
   ┌─→ 玩家按 WASD
   │      │
   │      ▼
   │   目标格 N 是身体格？ ──是──→ 截断 trail 到 N（§4.2 情况B）
   │      │否                          │
   │      ▼                            │
   │   合法移动？ ──否──→ 反馈（不动），回输入
   │      │是
   │      ▼
   │   头部移到 N，trail 入队 N，按 L 弹出多余尾格
   │      │
   │      ▼
   │   N 是食物？ ──是──→ L+=2，食物消失  ←──┐
   │      │否                                │
   │      ▼                                  │
   │   步数 +1（截断也算）                   │
   │      │                                  │
   │      ▼                                  │
   │   步数 % 6 == 0？ ──否──┐               │
   │      │是                │               │
   │      ▼                  │               │
   │   所有机关 +1 阶段      │               │
   │   占格更新（§5.5 跳过） │               │
   │   生长动画（阻塞输入）  │               │
   │      │                  │               │
   │      ▼                  │               │
   │   头部到终点？ ──是──→ 胜利界面 ◀──────┘
   │      │否
   │      ▼
   │   BFS: 有通路？ ──否──→ 失败界面
   │      │是
   │      ▼
   └  （回输入）
```

> 胜利检测在 BFS 之前：先看头部是否到终点，再到 BFS。机关生长后也需重检胜利（虽然生长不移动头部，但保险）。

## 9. 胜负条件

| 结果 | 触发 | 反馈 |
|------|------|------|
| **胜利** | 头部踏入终点格 `E` | 胜利动画 + 结算（步数/用时/食物数）→ 下一关/重开/退主界面 |
| **失败** | BFS 检测无通路（§7） | 失败提示 → 重开/退主界面 |
| **主动重开** | 玩家按 R 或 HUD 按钮 | 立即重载当前关 |
| **退主界面** | HUD 按钮 / Esc | 回主菜单（线性解锁进度保留） |

> 无超时、无步数上限、无评级——解谜友好，仅记录步数供玩家自评。

## 10. 关卡设计

### 10.1 关卡数据结构（`Resources/Config/LevelDefinition.tres`）
| 字段 | 类型 | 说明 |
|------|------|------|
| `LevelID` | int | 关卡编号（1–8） |
| `GridSize` | Vector2i | 默认 (32,32) |
| `StartCell` | Vector2i | 起点 S（=尾部固定点） |
| `GoalCell` | Vector2i | 终点 E |
| `InitialMaxLen` | int | 初始 L，默认 3 |
| `Obstacles` | Array[Vector2i] | 障碍格 |
| `Foods` | Array[Vector2i] | 食物格 |
| `Mechanisms` | Array[{center:Vector2i, init_lv:int}] | 机关中心与初始阶段 |
| `IsTutorial` | bool | 是否教程关 |

### 10.2 关卡序列（8 关）

| # | 类型 | 教学点 | 建议配置 |
|---|------|--------|---------|
| L01 | 教程 | 基础移动 + 身体轨迹 | 无机关，1 食物，距终点 ≤ L |
| L02 | 教程 | 吃食物 +L 扩展范围 | 1 机关（占位不生长？或距玩家远），2 食物 |
| L03 | 教程 | 机关生长（步数驱动） | 1 机关，引导玩家走 6 步看机关长 |
| L04 | 教程 | 踏回身体截断重规划 | 设一个需要折返的关卡 |
| L05 | 正式 | 单机关路径权衡 | 1 机关 2 食物，机关位置关键 |
| L06 | 正式 | 多机关同步生长 | 2 机关，步数推进同步扩张 |
| L07 | 正式 | 占格冲突与安全格 | 机关形状与玩家身体博弈 |
| L08 | 正式 | 综合谜题 | 2–3 机关 + 多食物，组合最优解 |

### 10.3 设计要点
- **必经食物**：起点到终点距离 > 初始 L 时，必须吃食物补 L。
- **机关位置**：中心放哪决定扩张后堵哪条路；高明设计让"看似多余的食物"成为陷阱（绕路吃食物多走步数 → 机关多长一次）。
- **多解 vs 唯一解**：建议关卡有 2–3 条可行路线，避免试错挫败。
- **教程关文案**：L01–L04 用浮字/气泡提示操作与机制。

## 13. 视觉与音频方向

| 项 | 方向 |
|----|------|
| 美术风格 | **暂缓**——先用纯色/线框占位，原型验证后再定（像素/矢量/手绘） |
| 配色（占位） | 主角暖色、机关冷色、食物亮色、终点高亮，确保对比清晰 |
| 主角 | 头=人物，经"管道"连到尾=机器；身体=管道瓦片（中段直/弯连接件 + 头/尾格端点半截瓦垫于其下）；头/尾占位为圆贴图（大于单格、接口点锚定）；起步/回到起点时头叠放在尾机器上 |
| 机关 | 几何/植物形态，生长有"绽放"动画 |
| 食物 | 发光小物（果实/能量球） |
| 终点 | 门户/光柱高亮 |
| BGM | 轻快解谜风，循环不腻 |

## 14. 实现要点（给脚本开发）

> 落到本项目架构，引用 autoload 与基类。

### 14.1 网格系统 `Scripts/Systems/GridSystem.gd`
- 维护 `cells: Array[Cell]`（1024 格），每格存类型（空/障碍/机关/食物/终点）。
- API：
  - `is_walkable(cell: Vector2i) -> bool`（含机关占格判定，排除被跳过的格）
  - `has_path_to_goal(from: Vector2i) -> bool`（BFS，供失败检测）
  - `get_mechanism_cells() -> Array[Vector2i]`
  - `apply_mechanism_growth()`（所有机关 +1 阶段，处理占格冲突）

### 14.2 主角 `Scripts/Entities/Player/Player.gd`
- 维护 `trail: Array[Vector2i]`、`max_len: int = 3`、`move_count: int = 0`。
- API：
  - `try_move(dir: Vector2i) -> void`（处理情况 A/B，更新 trail，吃食物，触发步数/生长/胜利/失败检测）
  - `get_body_cells() -> Array[Vector2i]`（= trail）
  - `get_actual_len() -> int`（= len(trail)）
- 关键逻辑（伪码）：
  ```gdscript
  func try_move(dir):
      var n = head + dir
      move_count += 1
      if n in trail:                      # 情况 B：截断
          trail = trail.slice(0, trail.find(n) + 1)
      else:                               # 情况 A：合法移动
          if not is_walkable(n): return   # 判定失败不动（步数是否回退？见 §14.8）
          trail.append(n)
          if len(trail) > max_len + 1:     # 保留 trail[0]=S
              trail.remove_at(1)
          if n == food: eat_food(n)
          if n == goal: win(); return
      if move_count % 6 == 0:
          grid.apply_mechanism_growth()   # 阻塞输入动画
          if head == goal: win(); return  # 生长后重检
      if not grid.has_path_to_goal(head):
          fail()
  ```

### 14.3 机关 `Scripts/Entities/Mechanism.gd`
- `lv: int`、`center: Vector2i`。
- 静态函数 `shape(lv: int) -> Array[Vector2i]` 返回**相对中心的偏移列表**（含 (0,0) 中心）。
- 形状表实现：
  - Lv0: `[(0,0)]`
  - Lv1: `[(0,0), (0,±1), (±1,0)]`（十字+中心）
  - Lv2: `[(0,0)] + 3×3 = 9 格`
  - Lv3: `[(0,0)] + 曼哈顿≤2 = 13 格`
  - Lv4: `[(0,0)] + 5×5去4角 = 21 格`
- `grow()`：lv = min(lv+1, 4)，调用 `GridSystem` 重新计算占格（跳过被身体占的格）。

### 14.4 失败检测接入
- `Player.try_move()` 末尾 → `GridSystem.has_path_to_goal(head)` → 失败则 `GameManager.end_game({"win": false})`。
- 机关生长后也调一次。
