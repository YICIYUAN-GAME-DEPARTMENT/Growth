## 1. 产品概述

| 项 | 内容 |
|----|------|
| 类型 | 2D 俯视网格解谜 |
| 节奏 | 回合制：每按一次方向键走 1 格，无实时压力 |
| 单关目标时长 | 1–5 分钟 |
| 内容规模 | 8 关（1–4 教程 / 5–8 正式） |
| 入口/解锁 | 线性解锁，通关解锁下一关 |
| 完成态记录 | 仅记录每关步数（不评级、无时限惩罚） |
| 目标平台 | Windows 桌面（Godot 导出 exe）；暂不要求 Web/移动 |

### 1.1 一句话概念
主角的**尾部钉死在起点**、身体像绳子延伸到头部；吃食物能增长最大身长，但每走 6 步场上的**机关**会同步扩张、堵死路径。玩家必须规划路线，在"够得着终点"和"路被堵死"之间找到解。

### 1.2 核心张力
**扩张可达范围 ↔ 机关随时间（步数）扩张切断通路。**

## 2. 术语与符号

> 全文统一使用以下术语；代码与文档保持一致。

| 术语 | 符号 | 定义 |
|------|------|------|
| 网格 | — | 由 `grid_size`（默认 32×32）定义的方形格世界；`Vector2i` 表示格坐标 |
| 主角 | Player | 由 头部(head)+身体轨迹 组成；尾部固定在起点 |
| 起点 | S | 主角锚点（尾部所在格），不可变 |
| 轨迹 | trail | `[S,…,head]`，主角走过的格序列（身体=轨迹） |
| 实际身长 | len(trail) | 轨迹含 S 的格数，≤ L |
| 最大身长 | L | 身长上限；初始 3，吃食物 +2；HUD 显示 L |
| 截断 | — | 头部踏入自身身体某格，撤销其后轨迹，可重规划 |
| 步数 | — | 有效移动/截断计数器；每 6 步触发机关生长 |
| 机关 | Mechanism | 含中心格、分阶段生长的障碍物；中心格恒占 |
| 阶段 | lv | 机关生长阶段 0–4；lv0 只占中心 1 格 |
| 占据格 | mech_cells | 机关已占据的格集合（并集），与障碍等同不可走 |
| 食物 | Food | 每格一个；被头部踏入即吃：L+2，格变空地 |
| 障碍 | Obstacle | 静态不可走格 |
| 终点 | E | 头部踏入即胜利 |
| 死局 | — | 系统判定头部已无通路到 E（BFS），自动判负 |

## 3. 核心玩法概述

### 3.1 核心循环
```
选关 → 移动（1格/次，尾部不动，轨迹延伸）
     → 吃食物（L+2）或折返截断（重规划）
     → 每满 6 步机关全体扩张 → 空间收紧
     → 踏入终点 = 胜  |  无通路（BFS）= 负 → 重开
```

### 3.2 玩家决策模型
每步玩家实际上在选择：**当前 L 内能走到哪 → 是否值得绕路吃食物（代价=步数→机关多长）→ 何时放弃重来**。机关生长节奏是全局"时钟"，制造张力但不惩罚失误——失误表现为"死局即重开"。

## 4. 游戏规则（权威）

### 4.1 主角与移动

**4.1.1 模型**
- 尾部（S）固定整关；头部初始=S，关卡开始 trail=[S]、实际身长=1。
- L 初始=3；吃食物 +2；L 只增不减。
- 实际身长可因截断变小，重新移动后最多回填到 L。

**4.1.2 移动判定（方向键）**
1. 目标格 `N` = 头 + 方向（仅上下左右，禁斜）。
2. 若 `N ∈ trail`（自身身体）→ **情况 B 截断**（见 4.1.3）。
3. 否则需同时满足才允许进入 `N`：
   - `N` 在网格内；
   - `N` 非障碍；
   - `N` 非机关占据格（含中心）；
   - `N` 非自身身体格（不含则进入情况 B，见上）。
4. 判定通过 → head=N，trail 追加 N；若 `len(trail) > L`，删除 `trail[1]`（保留 `S=trail[0]`）。
5. `N` 为食物 → 吃食物（4.4）；`N` 为 E → 胜利（4.7）。
6. **无效移动（撞障碍/机关/越界）**：头部不动、不计步、无机关生长；播放碰撞反馈（可选）。

**4.1.3 截断（踏回身体）**
- 允许 head 移入 trail 中任意格 `trail[k]`：trail 截为 `[S…trail[k]]`，其后轨迹撤销。
- 实际身长 = k+1；**算 1 步**（进计数器、可触发机关生长）。
- 踏入 S = 完全重置身体（实际身长=1）。
- 截断不会触发吃食物/胜利判定（食物格不会留在 trail 中）。

> 步数计数规则：**仅有效移动与截断 +1**；无效移动不计步（权威，取代 v0.2 §14.8 待定项）。

### 4.2 机关与生长

**4.2.1 机关形态（权威表）**

中心格 **C 恒占**。生长逐级嵌套扩张（lv 越高级集合包含低级）。

| lv | 总占格(含中心) | 相对 C 的形状 | 示意 |
|----|--------------|--------------|------|
| 0 | 1 | 仅 C | `C` |
| 1 | 5 | 中心 + 上下左右十字 | `·X· / XCX / ·X·` |
| 2 | 9 | 3×3 方块 | `XXX / XCX / XXX` |
| 3 | 13 | 5×5 菱形（曼哈顿≤2） | 菱形 |
| 4 | 21 | 5×5 去 4 角 | `25−4=21` |

> 去中心扩散区对应 **0 / 4 / 8 / 12 / 20**（与初始设计一致）。形状偏移在 `Mechanism.shape(lv)` 实现，属工程（见开发文档 §5.3），数值规则以本表为准。

**4.2.2 生长触发**
- 全局步数计数；当步数首次达到 **6 的倍数**（6/12/18…）时，**所有机关同步 +1 阶段**（不可逆，lv 封顶 4）。
- 生长与食物无关；食物只加 L。

**4.2.3 占格与冲突（身体阻挡）**
- 每次生长：机关尝试占据 `shape(lv)` 全部格；
- 若某目标格**正被玩家身体（trail）占据** → 本次跳过该格，但 **lv 照常 +1**；
- 已跳过格在**后续生长**重算 shape 时若仍属于该机关形状且玩家已离开 → 再尝试占据；若已不属于（形状只增不减，故不会发生）→ 保持空。形状单调扩展 ⇒ 跳过格只会被占晚、不会永远丢失资格（除玩家持续站桩）。
- 终局判定（BFS）按实际占据结果计算；被跳过的格**不算机关障碍**。

**4.2.4 动画与输入锁**
- 生长动画 ≤0.3s；期间锁输入，玩家按键**直接丢弃**（不排队）。

### 4.3 食物
- 位置由关卡 `.tres` 固定；每格一个；不重生。
- 头部踏入食物格：食物消失，**L+2**，不触发机关生长。
- 食物格被机关覆盖时不可再获得（关卡校验应避免关键食物被覆盖，见 §6.3）。

### 4.4 死局判定（BFS）
- **触发时机**：每次有效移动/截断后；每次机关生长动画结束后。
- 判定：以 head 为起点、E 为终点 BFS；可走格 = 非障碍、非 `mech_cells`；**忽略身长、忽略自身身体**（假设能无限延伸）。
- 无通路 ⇒ 判负并弹失败界面（提示重开/退出）；有通路则游戏继续。
- 判定顺序：先查"head 是否已在 E"（胜利优先于死局）。

### 4.5 胜负与流程
| 结果 | 条件 | 行为 |
|------|------|------|
| 胜利 | head 踏入 E | 结算：本关步数/食物；解锁下一关并保存；可 下一关/重开/回选关 |
| 失败（死局） | BFS 无通路 | 弹失败界面：重开/回选关 |
| 主动重开 | R 键 / HUD 按钮 | 重置当前关（数据与进度） |
| 退出 | HUD 按钮 / Esc | 回主界面（已通关进度已保存） |

无超时、无步数上限、无评级；步数仅供结算显示与自评。

## 5. 界面与操作

### 5.1 画面布局
```
┌──────────────────────────────────────────────┐
│ HUD：L: 5   食物 2/4   步数 18   [重开][退出]│
├──────────────────────────────────────────────┤
│  World：32×32 网格                           │
│   S(起点·尾) E(终点) 主角轨迹 食物(F)        │
│   机关(随阶段扩张) 障碍(#)                   │
└──────────────────────────────────────────────┘
```

### 5.2 场景流
```
主菜单 ──▶ 关卡选择（线性解锁，锁定关置灰）
   │              │
   └──── 胜利/失败结算 ◀── 关卡（Level.tscn + LVL_*.tres）
                   └──▶ 下一关 / 重开 / 回选关
```

### 5.3 输入映射
| 动作 | 按键 | InputAction | 状态 |
|------|------|-------------|------|
| 上/下/左/右 | WASD / 方向键 | `move_up/down/left/right` | 已配 |
| 重开 | R | `restart` | 需在 `project.godot` 新增 |
| 暂停 | Esc | `pause` | 已配（暂停后覆盖层含 继续/重开/退出） |
| UI 确认/取消 | Enter / Esc | `ui_accept`/`ui_cancel` | 引擎默认 |

### 5.4 HUD 元素
| 元素 | 内容 | 刷新时机 |
|------|------|---------|
| 最大身长 | `L: n` | 吃食物后 |
| 食物 | `食物: eaten/total` | 吃食物后 |
| 步数 | `步数: n` | 每次有效移动/截断后 |
| 重开按钮 | 重开 | 点击 → 重载当前关 |
| 退出按钮 | 退出 | 点击 → 回主界面（进度已存） |
| 机关阶段提示 | （教程/可选）当前 lv | 生长后 |

### 5.5 反馈清单（最低标准）
| 事件 | 反馈 |
|------|------|
| 有效移动 | 移动音 + 视觉更新 |
| 无效移动 | 轻"受阻"音 + 无位移 |
| 截断 | 特殊音/身体回缩动画 |
| 吃食物 | 进食音 + L 数字弹动 |
| 机关生长 | 生长音 + 扩张动画 + 输入锁(≤0.3s) |
| 胜利 | 上扬音 + 结算面板 |
| 死局 | 低沉音 + 失败面板 |

## 6. 关卡与内容

### 6.1 关卡清单（8 关，权威）
| 关 | 类型 | 教学点 | 建议配置 |
|----|------|--------|---------|
| 1 | 教程 | 移动与轨迹、身长含义 | 无机关；1 食物；E 在初始 L 可达距离内 |
| 2 | 教程 | 食物 +L 扩展可达 | 2 食物，需吃至少 1 才可及 |
| 3 | 教程 | 机关生长（步数时钟） | 1 机关；引导观察第 6 步扩张 |
| 4 | 教程 | 踏回截断重规划 | 需折返的布局；1–2 食物 |
| 5 | 正式 | 单机关路径权衡 | 1 机关 + 2 食物 |
| 6 | 正式 | 多机关同步扩张 | 2 机关 |
| 7 | 正式 | 机关与身体博弈 | 机关中心贴近常用路径 |
| 8 | 正式 | 综合 | 2–3 机关 + 多食物，多解但最优存在 |

### 6.2 关卡数据文件
- 每关一个 `Resources/Levels/LVL_<nn>_<名>.tres`（LevelDefinition）。字段见 [开发文档](../开发文档.md) §5.2。
- 生成/编辑用 Godot 编辑器或关卡工具；**不手工改二进制**。

### 6.3 关卡校验（发布前强制）
1. S、E、食物、机关中心互不重叠，且不在障碍上。
2. **初始即可走**：head=S 时 BFS 到 E 有通路（忽略身长）。
3. 关键食物（通关必需的 +2）不应落在任何机关 5 阶段形状覆盖区内（除非设计上允许"放弃该食物改道"）。
4. 教程关有明确引导文案（第 1–4 关）。
5. 验收用例（每关）在 §8 中由 QA 依关卡跑通。

## 8. 验收标准

> QA 与开发者据此回归；每条 = 可执行检查项。所有关卡共性的放 C-通用，逐关放 C-Lnn。

### C-通用（全部关卡）
| 编号 | 验收项 |
|------|--------|
| C-01 | 关卡从选关进入即重置：trail=[S]、实际身长=1、L=3（或关卡设定值）、步数=0、机关回到初始 lv、食物全在。 |
| C-02 | 方向键移动 1 格/次；斜向与连按合并正确；目标在界外/障碍/机关中心时不位移且不计步。 |
| C-03 | 身体=trail；当 len(trail)=L 后再前进，`S` 后一格被回收，实际身长保持 ≤L。 |
| C-04 | head 踏入自身身体格：trail 截断到该格，其后撤销，身长变为 k+1，步数+1。 |
| C-05 | head 踏入 S：trail=[S]，身长=1，步数+1。 |
| C-06 | 吃食物：食物消失、L+2、机关不变、步数+1（该次移动计入）。 |
| C-07 | 每第 6 次有效移动后：所有未满级机关 +1 lv；形状按 1/5/9/13/21 逐级正确；中心恒占。 |
| C-08 | 生长时被 body 占的新格跳过但机关 lv 仍+1；玩家离开后、后续生长若该格仍在形状内则占据。 |
| C-09 | 生长动画期间方向键输入被丢弃；动画 ≤0.3s 后恢复。 |
| C-10 | head 到 E：立即胜利；结算显示 本关步数/食物；成功解锁下一关。 |
| C-11 | BFS 无通路（head≠E）→ 自动判负并弹面板；重启后关卡状态正确重置。 |
| C-12 | R / 重开按钮：重置本关；退出按钮/Esc：回主界面，进度已保存。 |
| C-13 | HUD 的 L/食物/步数随事件即时刷新，与内部状态一致。 |
| C-14 | 游戏内无硬编码数值（均来自 Balance/关卡 .tres）；修改 Balance.tres 生效无需改代码。 |

### C-Lnn（逐关）
| 编号 | 验收项 |
|------|--------|
| C-L01 | 不看教程提示可自行移动到 E；含身长自动回收展示。 |
| C-L02 | 必须吃到 ≥1 食物才能到 E；确认 +2 生效。 |
| C-L03 | 引导第 6 步机关扩张；E 仍在可达范围。 |
| C-L04 | 存在必须"折返截断"才能走通（或最优）的解法。 |
| C-L05..08 | 有解且验收路径 ≤ 设计步数（§6.1 建议配置内）；无意外死局陷阱（若设计有意，须有提示）。 |

## 9. 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | 32×32 下每帧稳定 60fps；BFS 单次 < 1ms；机关动画不卡顿 |
| 稳定 | 胜利/失败/重开连续切换无报错、无残留节点 |
| 存档 | `user://` 读写安全；首次无存档时默认解锁第 1 关 |
| 输入 | 键盘仅依赖 `project.godot` 动作，支持手柄可后补 |
| 可维护 | 规则集中在 Balance/LevelDefinition + 本文档；禁止"脚本内改规则" |
| 兼容 | Godot 4.7 stable 零错误导入；无第三方插件 |
