## 1. 产品概述

| 项 | 内容 |
|----|------|
| 类型 | 2D 俯视网格解谜 |
| 节奏 | 回合制：每按一次方向键走 1 格，无实时压力 |
| 单关目标时长 | 1–5 分钟 |
| 内容规模 | 8 关（1–4 教程 / 5–8 正式），文件放 `Scenes/Levels/`，运行自动发现 |
| 入口/解锁 | 主菜单→选关；**测试期全开**（不做关卡锁定；后续可切线性解锁） |
| 完成态记录 | 仅记录每关步数（不评级、无时限惩罚） |
| 目标平台 | Windows 桌面（Godot 导出 exe）；暂不要求 Web/移动 |

### 1.1 一句话概念
主角的**尾部钉死在起点**、身体像绳子延伸到头部；吃食物能增长最大身长，但每走 6 步场上的**机关**会同步扩张、堵死路径。玩家必须规划路线，在"够得着终点"和"路被堵死"之间找到解。

### 1.2 核心张力
**扩张可达范围 ↔ 机关随时间（步数）扩张切断通路。**

## 2. 术语与符号

> 全文统一使用以下术语；代码与文档保持一致。

| 术语 | 符号 | 定义 |
|------|------|------|
| 网格 | — | 由 `grid_size`（默认 32×32）定义的方形格世界；`Vector2i` 表示格坐标 |
| 主角 | Player | 由 头部(head)+身体轨迹 组成；尾部固定在起点 |
| 起点 | S | 主角锚点（尾部所在格），不可变 |
| 轨迹 | trail | `[S,…,head]`，主角走过的格序列（身体=轨迹） |
| 实际身长 | len(trail) | 轨迹含 S 的格数，≤ L |
| 最大身长 | L | 身长上限；初始 3，吃食物 +2；HUD 显示 L |
| 截断 | — | 头部踏入自身身体某格，撤销其后轨迹，可重规划 |
| 步数 | — | 有效移动/截断计数器；每到达周期 N（默认 6，可单关覆盖）触发一次机关生长 |
| 机关 | Mechanism | 含中心格、分阶段生长的障碍物；中心格恒占 |
| 阶段 | lv | 机关生长阶段 0–4；lv0 只占中心 1 格 |
| 占据格 | mech_cells | 机关已占据的格集合（并集），与障碍等同不可走 |
| 食物 | Food | 每格一个；被头部踏入即吃：L+2，格变空地 |
| 障碍 | Obstacle | 静态不可走格 |
| 终点 | E | 头部踏入即胜利 |
| 死局 | — | 系统判定头部无通路到 E，或当前 L 内够不到 E 且够不到任何食物（BFS），自动判负 |

## 3. 核心玩法概述

### 3.1 核心循环
```
选关 → 移动（1格/次，尾部不动，轨迹延伸）
     → 吃食物（L+2）或折返截断（重规划）
     → 每满 6 步机关全体扩张 → 空间收紧
     → 踏入终点 = 胜  |  无通路/身长不够（BFS）= 负 → 重开
```

### 3.2 玩家决策模型
每步玩家实际上在选择：**当前 L 内能走到哪 → 是否值得绕路吃食物（代价=步数→机关多长）→ 何时放弃重来**。机关生长节奏是全局"时钟"，制造张力但不惩罚失误——失误表现为"死局即重开"。

## 4. 游戏规则（权威）

### 4.1 主角与移动

**4.1.1 模型**
- 尾部（S）固定整关；头部初始=S，关卡开始 trail=[S]、实际身长=1。
- L 初始=3；吃食物 +2；L 只增不减。
- 实际身长可因截断变小，重新移动后最多回填到 L。

**4.1.2 移动判定（方向键）**
1. 目标格 `N` = 头 + 方向（仅上下左右，禁斜）。
2. 若 `N ∈ trail`（自身身体）→ **情况 B 截断**（见 4.1.3）。
3. 否则需同时满足才允许进入 `N`（**情况 A**）：
   - `N` 在网格内；
   - `N` 是**已涂地板**（Ground 层实际涂格，地板=可走区；Ground 未涂=背景/不可走）；
   - `N` 非障碍；
   - `N` 非机关占据格（含中心）；
   - **身体有富余**：进入后 `len(trail)+1 ≤ L`，即 `len(trail) < L`（身长硬上限，权威，见 §3 术语）。
4. 判定通过 → head=N，trail 追加 N；trail 从 S 到 head 保持连续，长度恒 ≤ L（**无“弹出中部格”机制**）。
5. `N` 为食物 → 吃食物（4.4）；`N` 为 E → 胜利（4.7）。
6. **无效移动**：越界 / 撞障碍 / 机关占格 / 身长已达上限时进入空格 → 头部不动、不计步、无机关生长；播放碰撞反馈（可选）。

> **身长受限语义（权威）**：身体从 S 连续铺到 head，最多 L 格。因此 head 相对 S 的最长步数 ≤ L−1；当 trail 已达 L 时，前进空格会被禁止，玩家只能：吃食物（先要吃到的食物必在现 L 可达内）→ 回身截断（4.1.3）→ 或重开。

**4.1.3 截断（踏回身体）**
- 允许 head 移入 trail 中任意格 `trail[k]`：trail 截为 `[S…trail[k]]`，其后轨迹撤销（连续路径保持）。
- 实际身长 = k+1；**算 1 步**（进计数器、可触发机关生长）。
- 踏入 S = 完全重置身体（实际身长=1）。
- 截断不会触发吃食物/胜利判定（食物格不会留在 trail 中）。

> 步数计数规则：**仅有效移动与截断 +1**；无效移动不计步（权威）。

### 4.2 机关与生长

**4.2.1 机关形态（权威表）**

中心格 **C 恒占**。生长逐级嵌套扩张（lv 越高级集合包含低级）。

| lv | 总占格(含中心) | 相对 C 的形状 | 示意 |
|----|--------------|--------------|------|
| 0 | 1 | 仅 C | `C` |
| 1 | 5 | 中心 + 上下左右十字 | `·X· / XCX / ·X·` |
| 2 | 9 | 3×3 方块 | `XXX / XCX / XXX` |
| 3 | 13 | 5×5 菱形（曼哈顿≤2） | 菱形 |
| 4 | 21 | 5×5 去 4 角 | `25−4=21` |

> 去中心扩散区对应 **0 / 4 / 8 / 12 / 20**（与初始设计一致）。形状偏移在 `Mechanism.shape(lv)` 实现，属工程（见开发文档 §5.3），数值规则以本表为准。

**4.2.2 生长触发**
- 全局步数计数；每当有效步数达到**本关生长周期 N**（默认 6，可单关覆盖）的倍数时，**所有机关生长 1 次**：未满级机关 **+1 阶段**（不可逆，阶段封顶本关最高 cap）；**满级机关维持阶段、照常执行刷新**（见 4.2.3）。
- 生长与食物无关；食物只加 L。

**4.2.3 占格与冲突（身体阻挡）**
- 每次生长（含满级后的刷新）：机关尝试占据 `shape(level)` 全部格；
- 若某目标格**正被玩家身体（trail）占据** → 本次跳过该格；未满级时 **lv 照常 +1**；
- 已跳过格在**后续任一次生长（含满级后）**重算 shape 时若仍属于该机关形状且玩家已离开 → 再尝试占据；若已不属于（形状只增不减，故不会发生）→ 保持空。形状单调扩展 ⇒ 跳过格只会被占晚、不会永远丢失资格（除玩家持续站桩）。**满级后阶段不变，但每次到达周期仍重扫 shape 补齐上述空出的格，即"满级机关一直长满"。**
- 终局判定（BFS）按实际占据结果计算；被跳过的格**不算机关障碍**。

**4.2.4 动画、即时生效与输入锁**
- **占格即时生效（权威）**：机关 +1 阶段与占格更新在生长发生当帧同步完成（不等动画播完），随后动画播放并锁输入，动画结束后再跑死局检查。
- 生长动画 ≤0.3s；期间锁输入，玩家按键**直接丢弃**（不排队）。

### 4.3 食物
- 位置由关卡场景摆放固定；每格一个；不重生。
- 头部踏入食物格：食物消失，**L+2**，不触发机关生长。
- 食物格被机关覆盖时不可再获得（关卡校验应避免关键食物被覆盖，见 §6.3）。

### 4.4 死局判定（BFS）
- **触发时机**：每次有效移动/截断后；每次机关生长动画结束后。
- **连通性判定**：以 head 为起点、E 为终点 BFS；可走格 = **已涂地板**（Ground 实际涂格）且非障碍、非 `mech_cells`；**忽略身长、忽略自身身体**（假设能无限延伸）。无通路 ⇒ 判负并弹失败界面（提示重开/退出）。
- **身长可达判定**（仅在实际身长已达上限 `len(trail) == L` 时执行）：以 S 为源 BFS（可走格同上；身体不算阻挡——头可随时踏回身体截断重规划），得各格最短步数；head 经重规划等效"从 S 出发最多走 L−1 步"。若 E 与**所有剩余食物**的最短步数均 > L−1 ⇒ L 永不再增长（吃食物是唯一途径）且可达范围只缩不增（机关不可逆）⇒ 判负。身长未满时玩家可继续前进探索，不判定。
- 判定顺序：先查"head 是否已在 E"（胜利优先于死局）→ 连通性判定 → 身长可达判定；任一死局条件成立即判负，否则游戏继续。

### 4.5 胜负与流程
| 结果 | 条件 | 行为 |
|------|------|------|
| 胜利 | head 踏入 E | 结算：本关步数/食物；记录 SaveManager；可 **下一关**（按关卡列表进入下一位；已是最后一关则返回选关）/ 重开本关 / 返回选关 |
| 失败（死局） | §4.4：无通路 或 身长不够 | 弹失败界面：重开/回选关 |
| 主动重开 | R 键 / HUD 按钮 | 重置当前关（数据与进度） |
| 退出 | HUD 按钮 / Esc | 回选关界面（记录已保存） |

无超时、无步数上限、无评级；步数仅供结算显示与自评。关卡锁定**测试期禁用**（LevelSelect 全开）。

## 5. 界面与操作

界面文案只保留标题、功能、操作与状态信息。除非需求明确指定，禁止添加天气、季节、氛围副标题、鼓励句、抒情句及额外操作提示，也不将既有功能名称改写为花园化称呼。关卡内暂不使用花园背景，保持原有空白背景。剧情演出（§5.6）中的对白为**作者撰写的内容数据**，不在上述界面文案禁令范围内。

### 5.1 画面布局
```
┌──────────────────────────────────────────────┐
│ HUD：L: 5   食物 2/4   步数 18   [重开][退出]│
├──────────────────────────────────────────────┤
│  World：32×32 网格                           │
│   S(起点·尾) E(终点) 主角轨迹 食物(F)        │
│   机关(随阶段扩张) 障碍(#)                   │
└──────────────────────────────────────────────┘
```

### 5.2 场景流
```
MainMenu（开始界面）
  │ 开始 / 设置 / 退出
  │ 点击"开始"
  ▼
LevelSelect（选关，扫描 Scenes/Levels/Level_*.tscn，测试期全开；按关卡列表**每关一行**显示 `序号 | 关卡名`，点击进入）
  │ 点击某关
  ▼
Level 场景（Level_<nn>.tscn）—— HUD 顶栏 + 网格世界
  │ 胜利/失败 → 结算覆盖层
  ▼
下一关（最后一关则返回选关）/ 重开本关 / 返回选关
```

### 5.3 输入映射
| 动作 | 按键 | InputAction | 状态 |
|------|------|-------------|------|
| 上/下/左/右 | WASD / 方向键 | `move_up/down/left/right` | 已配 |
| 重开 | R | `restart` | 已配 |
| 暂停 | Esc | `ui_cancel` | 已配（暂停菜单含 继续/重开/退出；再次按 Esc 继续） |
| UI 确认/取消 | Enter / Esc | `ui_accept`/`ui_cancel` | 引擎默认 |

### 5.4 HUD 元素
| 元素 | 内容 | 刷新时机 |
|------|------|---------|
| 剩余步数 | 左上角圆角正方形内仅显示数字；值为最大身长减当前身体长度 | 每次有效移动、截断或吃食物后 |
| 花瓣提供的步长 | 紧随剩余步数；每片花瓣（食物）为最大身长增加的格数（Balance `food_len_gain`，可被关卡 `food_len_gain_override` 覆盖） | 进关即显示 |
| 花丛（机关）下次生长剩余步数 | 紧随花瓣之后；值为距下次全体机关生长的剩余有效步数（`growth_step_interval` 或其关卡 override，默认 6）；本关无机关时隐藏 | 进关即显示；每次有效移动 / 截断后刷新 |
| 关卡标题 | 顶栏顶部中央显示 `第 N 关 · 关卡名`（N = `level_id`，与选关列表序号一致） | 进关即显示 |
| 重开按钮 | 重开 | 点击 → 重载当前关 |
| 选关按钮 | 选关 | 点击 → 返回选关（记录已存） |
| 暂停菜单 | 继续 / 重开 / 退出 | Esc 打开；暂停期间停止关卡处理 |

### 5.5 反馈清单（最低标准）
按钮按下时（鼠标或键盘确认）播放统一的短促 Q 弹音效；禁用按钮不播放，暂停菜单可播放，切换场景不截断余音。不改变按钮响应时机。

| 事件 | 反馈 |
|------|------|
| 有效移动 | 移动音 + 视觉更新 |
| 无效移动 | 轻"受阻"音 + 无位移 |
| 截断 | 特殊音/身体回缩动画 |
| 吃食物 | 进食音 + L 数字弹动 |
| 机关生长 | 生长音 + 扩张动画 + 输入锁(≤0.3s) |
| 胜利 | 上扬音 + 结算面板 |
| 死局 | 低沉音 + 失败面板 |

### 5.6 剧情演出（AVG 覆盖层，可选）

每个触发点是否播剧情、播哪段，由**作者在关卡 Level 根节点独立配置**：`story_start / story_win / story_fail`（留空 = 该触发点不播）。

| 触发点 | 时机 | 行为 |
|--------|------|------|
| 开始 | 进关布局完成后 | 先播开场剧情，播完（含跳过）才可操作；重开 / 再次进入均重播 |
| 胜利 | head 踏入 E | 结算与存档信号先行，再播剧情；播完（含跳过）才弹结算面板 |
| 失败 | BFS 判负 / 身长不足 | 先播剧情，播完（含跳过）才弹失败面板 |

- 每段剧情一个独立剧本文件（JSON），一句只需写 `speaker` + `pose`；显示名与立绘由角色注册表 `Characters.json` 决定，**立绘切换与对话推进由系统自动完成**。
- 演出期间全屏覆盖；不弹暂停菜单（Esc = 整段跳过）；点击 / 回车 / 空格逐句推进（打字中先显示整句）。
- 剧本缺失 / 非法 / 未知角色姿态：告警并降级（该句无立绘或整段跳过），不中断关卡流程。

## 6. 关卡与内容

### 6.1 关卡清单（参考基线，非强约束）
| 关 | 类型 | 教学点 | 参考配置 |
|----|------|--------|---------|
| 1 | 教程 | 移动与轨迹、身长含义、食物 +L、机关扩张（第 6 步） | 1 机关 + 2 食物；E 在初始 L 可达距离内（已实现为 `Level_01_教学关1`） |
| 2 | 教程 | 食物 +L 扩展可达 | 2 食物，需吃至少 1 才可及 |
| 3 | 教程 | 机关生长（步数时钟） | 1 机关；引导观察第 6 步扩张 |
| 4 | 教程 | 踏回截断重规划 | 需折返的布局；1–2 食物 |
| 5 | 正式 | 单机关路径权衡 | 1 机关 + 2 食物 |
| 6 | 正式 | 多机关同步扩张 | 2 机关 |
| 7 | 正式 | 机关与身体博弈 | 机关中心贴近常用路径 |
| 8 | 正式 | 综合 | 2–3 机关 + 多食物，多解但最优存在 |

### 6.2 关卡文件（场景直编，权威）
- 每关 = 一个 **场景文件**：`Scenes/Levels/Level_<nn>_<名>.tscn`，根节点挂 `Level` 脚本。
- 关卡内容由设计者直接在场景里组织：`Ground`/`Obstacles` TileMapLayer 涂格（Ground=已涂地板可走区；障碍=被涂的格，涂在 Obstacles 层），实体放 `PlayerSpawn`（1 个）、`Food`（任意）、`Goal`（1 个）、`Mechanism`（任意，一个节点=机关核心）。所有节点在编辑器里拖动即吸附格子。
- 地图范围：**Ground/Obstacles 涂格 + 实体格的外接矩形**；完全空白才退回根节点导出的 `map_size`。**机关只在已涂地板格上占位**（可走区即机关可生长区，Ground 未涂=不可走也不长机关；越界不占，见 §4.2.4），设计机关时请为它预留已涂地板空间。
- **位置即所见**：World/Cam 为普通场景节点，运行时不自动移动/缩放——设计者摆哪游戏显示哪。
- 数值两级配置：**全局基准**在 `Resources/Config/Balance.tres`；**单关覆盖**在关卡根节点 `Level` 上导出 `initial_max_len_override / food_len_gain_override / mechanism_max_level_override / growth_step_interval_override`（0=沿用全局；见 [开发文档](../开发文档.md) §5.2/§5.5）。生长动画时长 `grow_anim_sec` 仅全局。

### 6.3 关卡校验（发布前强制）
1. PlayerSpawn / Goal / Food / Mechanism 中心互不重叠，不在 Obstacle 上，且**都落在已涂地板（Ground）格上**（地板=可走区）。
2. **初始即可走**：head=S 时 BFS 到 E 有通路（忽略身长）。
3. **身长可达校验**：按当前 L 硬上限逐食物推进，必须存在可达 E 的食物链（关卡设计期用编辑器试玩或校验脚本确认），否则无法通关。
4. 关键食物（通关必需的 +2）不应落在任何机关 5 阶段形状覆盖区内（除非设计上允许"放弃该食物改道"）。
5. 教程关有明确引导文案（第 1–4 关）。
6. 验收用例（每关）在 §8 中由 QA 依关卡跑通。

## 7. 数值配置（权威清单）

> 唯一权威出处。实现落到 `Balance.tres`（全局基准）与关卡场景（布局 + Level 根节点单关覆盖）。开发文档 §5.6 为其 QA 速查镜像。调整需走变更流程。

| 参数 | 初值 | 说明 |
|------|------|------|
| 网格大小 | 默认 32×32 | 仅当场景完全空白时由 `map_size` 兜底；涂格/放实体后取内容包围盒 |
| 初始最大身长 L | 3 | HUD 显示 L；**可单关覆盖**（Level 根节点，0=沿用全局） |
| 食物加 L | +2 | 仅 L；**可单关覆盖** |
| 机关最大阶段 | lv 4 | 0–4 共 5 档；**可单关覆盖**（cap 钳制 0–4） |
| 机关形状（含中心） | 1 / 5 / 9 / 13 / 21 | 逐级嵌套 |
| 机关去中心扩散区 | 0 / 4 / 8 / 12 / 20 | 同表 |
| 生长周期 | 默认每 6 步 | **可单关覆盖**；未满级机关 +1 阶段，满级机关维持阶段但照常刷新补格 |

| 计步 | 仅有效移动/截断 | 记录展示，无评级 |

## 8. 验收标准

> QA 与开发者据此回归；每条 = 可执行检查项。所有关卡共性的放 C-通用，逐关放 C-Lnn。

### C-通用（全部关卡）
| 编号 | 验收项 |
|------|--------|
| C-01 | 关卡从选关进入即重置：trail=[S]、实际身长=1、L=3（或关卡设定值）、步数=0、机关回到初始 lv、食物全在。 |
| C-02 | 方向键移动 1 格/次；斜向与连按合并正确；目标在界外/障碍/机关中心时不位移且不计步。 |
| C-03 | 身体=trail（S 到 head 连续）；进入空格后 trail 长度 ≤ L；当 len(trail)=L 时向前进入空格被禁止（不计步）。 |
| C-04 | head 踏入自身身体格：trail 截断到该格，其后撤销，身长变为 k+1，步数+1。 |
| C-05 | head 踏入 S：trail=[S]，身长=1，步数+1。 |
| C-06 | 吃食物：食物消失、L+2、机关不变、步数+1（该次移动计入）。 |
| C-07 | 每到达本关周期 N（默认 6，可单关覆盖）次有效移动后机关生长 1 次：未满级机关 +1 lv，形状按 1/5/9/13/21 逐级正确；中心恒占。占格在生长发生时同步生效（即时，不等动画播完）。 |
| C-08 | 生长时被 body 占的新格跳过；未满级 lv 仍 +1。玩家离开后、后续任一次生长（含满级后）若该格仍在形状内则占据——满级机关每次到周期仍刷新补齐空出的格。 |
| C-09 | 生长动画 ≤0.3s 期间方向键输入被丢弃；动画结束后恢复输入并做死局检查。 |
| C-10 | head 到 E：立即胜利；结算显示 本关步数/食物；步数记录到 SaveManager。 |
| C-11 | BFS 无通路（head≠E）→ 自动判负并弹面板；重启后关卡状态正确重置。 |
| C-12 | R / 重开按钮：重置本关；退出按钮/Esc：回选关界面，记录已保存。 |
| C-13 | HUD 的 L/食物/步数随事件即时刷新，与内部状态一致。 |
| C-14 | 数值无硬编码：初始 L / ΔL / 机关最高阶段 / 生长周期来自全局 Balance.tres，并可在关卡 Level 根节点 `*_override` 覆盖（0=沿用全局）直接调；`grow_anim_sec` 仅全局。布局来自场景摆放，脚本不含关卡数据。 |
| C-15 | 三触发点剧情在 Level 根节点留空时不播放，关卡行为与未配置剧情一致。 |
| C-16 | 配置 `story_start` 后：进关即播，播完/跳过后才可操作；播放期间方向键无效、R 重开可用；重开/再次进入均重播开场。 |
| C-17 | 配置 `story_win` / `story_fail` 后：胜负判定与存档信号先行，剧情播完（含跳过）后才弹结算/失败面板；无剧情时结算行为不变。 |
| C-18 | 剧情播放：立绘随句切换、打字机完整显示、点击/回车/空格推进、Esc 整段跳过；播放期不弹暂停菜单。 |
| C-19 | 剧本缺失/非法/未知角色姿态：告警并降级（该句无立绘或整段跳过），不中断关卡流程。 |

### C-Lnn（逐关）
| 编号 | 验收项 |
|------|--------|
| C-L01 | 不看教程提示可自行移动到 E；含身长自动回收展示。 |
| C-L02 | 必须吃到 ≥1 食物才能到 E；确认 +2 生效。 |
| C-L03 | 引导第 6 步机关扩张；E 仍在可达范围。 |
| C-L04 | 存在必须"折返截断"才能走通（或最优）的解法。 |
| C-L05..08 | 有解且验收路径 ≤ 设计步数（§6.1 建议配置内）；无意外死局陷阱（若设计有意，须有提示）。 |

## 9. 非功能需求

| 类别 | 要求 |
|------|------|
